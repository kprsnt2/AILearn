L55 · DPO: RLHF without RL, with the gradient checked numerically

DPO deletes the reward model by inverting a closed form — and in doing so deletes the constraint on anything the pairs never mentioned. This page derives it, checks the gradient to 1e-9, and then breaks it deliberately.

~28 min difficulty ●●●○○ build: DPO loss + gradient in pure Python
closed-form optimum implicit reward log-ratio margin beta as KL price reference policy off-policy collapse IPO margin bound ORPO

1 · Why it exists #

RLHF worked and was miserable to run. The InstructGPT recipe (arXiv:2203.02155) needs four models in memory — policy, reference, reward model, value model — plus a sampling loop, plus a reward model that you must train and then trust. DPO (arXiv:2305.18290) removes the reward model and the sampling loop by noticing that the RLHF objective has a closed-form optimal policy, and that policy can be inverted to recover the reward.

The failure DPO was invented to stop is therefore operational, not scientific: the reward model is a second, unaccountable model that silently redefines your objective. If it is mis-calibrated, the policy optimises the miscalibration, and you find out weeks later. DPO deletes that model, and in doing so deletes an entire class of failure — while introducing a different one, which is the subject of experiment 3.

DPO is not "preference learning without RL" in the sense of avoiding a tradeoff. It is what you get when you substitute the closed-form optimum of the KL-regularised objective into a Bradley–Terry likelihood. The two models in memory are the policy and a frozen reference; the pairs are the only data; and the optimisation is ordinary supervised learning on a contrast.

2 · The mental model #

The mental model: the KL-regularised objective from lesson 51 has an exact maximum

π*(y|x) = (1/Z(x)) · πref(y|x) · exp( r(x,y) / β ) Z(x) is a normaliser that depends only on the prompt. Solve for r and it becomes r(x,y) = β log(π*/πref) + β log Z(x).

Now put that reward into a Bradley–Terry comparison of two responses yw (chosen) and yl (rejected) to the same prompt. The prompt-only term β log Z(x) appears on both sides and cancels. What is left contains no reward model at all — only the policy and the reference:

P(yw ≫ yl) = σ( β [ log(πθ(yw|x)/πref(yw|x)) − log(πθ(yl|x)/πref(yl|x)) ] ) Two implicit rewards, each a log-ratio to the reference. Their difference is the margin, and the loss is −log σ(β · margin).

What "the policy is the reward" gets right

There is one model to train and one frozen copy to compare against. The constraint (don't move too far from πref) is built into the loss, not enforced by a penalty the optimiser can trade off badly.

Where it breaks

Offline pairs only constrain the comparisons they contain. A behaviour no pair mentions is unconstrained except by the reference term, which only slows drift; it does not stop it. DPO cannot explore, so it cannot discover a better answer than the better of the two it was shown.

3 · The mechanism #

Write the loss once, correctly, with log-probabilities summed over tokens:

LDPO(θ) = − E(x,yw,yl) [ log σ( β log(πθ(yw|x)/πref(yw|x)) − β log(πθ(yl|x)/πref(yl|x)) ) ] log π(y|x) = Σt log π(yt|x,y<t). Sum, never multiply: sequence probabilities underflow immediately.

Its gradient has a shape worth memorising, because every sibling method changes one piece of it:

∇θL = −β · σ(−β·margin) · [ ∇logπθ(yw|x) − ∇logπθ(yl|x) ] The weight σ(−β·margin) is the model's current probability of getting the pair WRONG. Pairs already won contribute almost nothing.

Two files below: dpo.py is the objective plus a hand-derived gradient, main.py checks the gradient against finite differences and then trains. Run them in the same directory with plain python main.py.

# dpo.py from L55 -- the objective and its gradient, five lines each. import math BETA = 0.1 def sig(z): if z >= 0: return 1 / (1 + math.exp(-z)) e = math.exp(max(z, -700)) return e / (1 + e) def logp(z, k): m = max(z) return z[k] - m - math.log(sum(math.exp(v - m) for v in z)) def dpo_parts(z, ref, ch=0, rj=1, beta=BETA): margin = (logp(z, ch) - logp(ref, ch)) - (logp(z, rj) - logp(ref, rj)) return -math.log(sig(beta * margin)), margin def dpo_grad(z, ref, ch=0, rj=1, beta=BETA): _, margin = dpo_parts(z, ref, ch, rj, beta) g = -beta * sig(-beta * margin) # dL/dmargin p = [math.exp(logp(z, k)) for k in range(len(z))] dlogp = lambda a, b: (1.0 if a == b else 0.0) - p[b] # d logp(a)/d z_b return [g * (dlogp(ch, b) - dlogp(rj, b)) for b in range(len(z))]
# main.py: gradient check (analytic vs finite difference), then DPO on a pair dataset # where one behaviour never appears. Run: python main.py import math from dpo import dpo_grad, dpo_parts, logp, BETA z = [0.2, -0.1, 0.5] # policy logits over [chosen, rejected, unmentioned] ref = [0.0, -0.4, 0.9] # frozen SFT reference, which likes 'unmentioned' L, margin = dpo_parts(z, ref) print(f"margin={margin:+.4f} beta*margin={BETA * margin:+.4f} loss={L:.4f}") g = dpo_grad(z, ref) h, fd = 1e-6, [] for b in range(3): zp = list(z) zp[b] += h fd.append((dpo_parts(zp, ref)[0] - L) / h) print("analytic grad :", [round(x, 6) for x in g]) print("finite diff :", [round(x, 6) for x in fd]) print("max abs error :", round(max(abs(a - b) for a, b in zip(g, fd)), 9)) p = [math.exp(logp(z, k)) for k in range(3)] pr = [math.exp(logp(ref, k)) for k in range(3)] print("policy P :", [round(x, 3) for x in p]) print("reference P :", [round(x, 3) for x in pr]) print("implicit reward beta*log(p/ref):", [round(BETA * math.log(a / b), 4) for a, b in zip(p, pr)]) # ---- now train: same pair type, 300 steps, and watch the unmentioned behaviour ---- w = [0.0, 0.0, 0.0] for _ in range(300): grad = dpo_grad(w, ref) w = [wi - 0.5 * gi for wi, gi in zip(w, grad)] pw = [math.exp(logp(w, k)) for k in range(3)] kl = sum(a * (math.log(a) - math.log(b)) for a, b in zip(pw, pr)) print("\nafter 300 DPO steps on pairs that never mention behaviour 2:") print(f" P(chosen)={pw[0]:.3f} P(rejected)={pw[1]:.3f} P(unmentioned)={pw[2]:.3f}") print(f" KL(policy || SFT reference) = {kl:.3f} nats")

The first block prints a max absolute error near 1e-9, which is what a correctly hand-derived gradient looks like. An error around 1e-2 means the coupling term was dropped and the log-probs were treated as independent.

Experiment 2 — read what the margin is made of

The same output prints the implicit reward β·log(π/πref) for each response before training.

P(chosen) = 0.324 reference 0.242 implicit reward = +0.029 P(rejected) = 0.240 reference 0.162 implicit reward = +0.039 margin = 0.029 - 0.039 = -0.010 -> beta*margin = -0.010 -> loss = 0.6982 the rejected answer has the HIGHER implicit reward. the pair asks for the GAP to flip, not for either absolute reward to rise. log 2 = 0.693 is the neutral starting point.

The rejected response outranks the chosen one on the implicit reward. DPO pushes on the difference of differences, so a loss near log 2 means the policy and reference order the pair the same way — not that the model is at chance, and not that anything is broken.

The script finishes by training 300 steps on pairs in which a third behaviour never appears, from a reference that likes it.

P(unmentioned) falls from the reference's 0.596 to about 0.004 and KL reaches about 1.39 nats, with zero pairs mentioning that behaviour. The reference term slows the drift; it does not bound it. If a capability disappeared after a DPO run, this is the mechanism, and the falsifier is simple: re-run with pairs that mention the behaviour. If it stops collapsing, coverage was the issue.

5 · Failure modes #

  • Off-policy collapse. Symptom: held-out graded accuracy falls while pairwise preference accuracy on the training distribution rises; KL to the reference grows without a matching capability gain. The pairs never covered a behaviour the model used to have.
  • β not written down. Symptom: nobody in the room can say what KL budget the run was allowed. β prices nats of drift in reward units; if it is a hyperparameter chosen by vibe, every comparison across runs is meaningless.
  • Reference not frozen (or not identical to SFT). Symptom: reference log-probs drift during training, the margin becomes self-referential, and loss collapses toward zero while behaviour does not improve. Check: reference log-probs must be bitwise identical at step 0 and step N.
  • Wrong reference: base instead of SFT. Symptom: the policy is pushed back toward pretrained behaviour and the formatting you paid SFT for degrades. The reference must be the checkpoint that already satisfies your format gate.
  • Length asymmetry in pairs. Symptom: chosen responses are systematically longer and the DPO model gets longer over training. The margin between log-probs is length-sensitive; balance pair lengths or add a length-normalised variant and measure both.
  • IPO / KTO / ORPO substituted without changing the diagnostics. Symptom: you swapped the loss and kept the gates that were designed for DPO's margin scale. IPO bounds the margin, KTO drops the pairing assumption, ORPO folds it into SFT — each changes what a "good loss" looks like.

Three immutable checks per DPO run: reference hashes equal at start and end; held-out pair accuracy and an independent graded eval both reported; and a KL-to-reference curve. Without the third you cannot tell a successful alignment run from a slow off-policy collapse.

7 · Self-check #

Q1. Starting from π* ∝ πref·exp(r/β), show where the Z(x) term goes in the DPO loss.

Reveal answer

Solving gives r(x,y) = βlog(π*/πref) + βlog Z(x). In Bradley-Terry the comparison is r(x,yw) − r(x,yl);the βlog Z(x) term is identical for both responses to the same prompt, so it cancels exactly. This is also why DPOrequires both responses to share the prompt — cross-prompt pairs would leave an un-cancelled Z term.

Q2. Quantitative: β=0.1, policy log-ratio for chosen is +0.3, for rejected is −0.2. Give the margin, β·margin, and the loss.

Reveal answer

margin = 0.3 − (−0.2) = 0.5. β·margin = 0.05. σ(0.05) = 0.5125, so loss = −log(0.5125) = 0.669.Note the scale: with β=0.1 a log-ratio gap of half a nat only produces a 0.05 margin, i.e. the loss is only slightlybelow log 2 — DPO is a very gentle objective per pair.

Q3. Why does the gradient weight σ(−β·margin) matter for dataset curation?

Reveal answer

It is the probability that the pair is currently being predicted wrong. Once a pair is comfortably won, its weight goes tozero and it stops teaching. So a dataset that is 80% easy pairs is 80% wasted compute; the marginal value of a pair ishighest where the model is uncertain. Curate toward hard, close pairs, and re-run hard-pair mining after each checkpoint.

Q4. Diagnostic: DPO loss falls from 0.69 to 0.42 over 1000 steps, held-out pair accuracy is 0.88, and the graded eval dropped 3 points. What happened and what is the check?

Reveal answer

Off-policy drift: the policy got better at the comparisons it was shown while losing behaviour the pairs never covered.Check: KL to reference at the final step. If it is above the budget implied by β, the run overshot; also measure thegraded eval restricted to prompts NOT in the pair dataset. If the drop is only on uncovered prompts, it is drift ratherthan a global regression, and the fix is coverage (more diverse pairs) or a smaller effective β.

Q5. Why must the reference be the SFT checkpoint rather than the base model, and what is the symptom of getting this wrong?

Reveal answer

The reference defines both the constraint and the implicit reward's zero point. Using the base model pulls the policy backtoward pretrained behaviour — you fight SFT for the rest of training. Symptom: instruction-following and format compliancedegrade while preference accuracy improves, and short prompts show a sudden reappearance of the model's pretrained stylistic quirks.
