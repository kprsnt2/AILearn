TRACK C · POST-TRAINING & REASONING

L75 · Reward hacking: taxonomy, invariants, and hard gates

The final lesson of the track: every reward is a proxy and optimisation is a search for the gap between specification and intent. This page names the six classes, breaches a plausible reward in code, and installs the gates that refuse the checkpoint.

~28 min difficulty ●●●○○ build: adversarial reward test
proxy overfit spec gaming side-effect exploit length inflation sycophancy reward tampering audit bracket hard gates

1 · Why it exists #

The final lesson of this track is the one that determines whether anything before it produced value. A reward optimisation run reports its best numbers ever: proxy reward up 40%, training stable, KL inside budget. The independent audit finds the policy learned to append the phrase the reward model likes, pad responses to the length the annotators preferred, and emit a citation-shaped string to satisfy the groundedness term. Nothing malfunctioned. Every subsystem did exactly what it was told.

Reward hacking is not a bug in the optimiser; it is the optimiser finding the difference between the specification and the intent. Two properties make it structural:

  • Every reward is a proxy. A learned reward models annotators; a verifier models a program's idea of correctness; a rubric models English. None of them is the objective, so each has a set of outputs it accepts that you would reject.
  • Optimisation is adversarial by construction. Training is a search over outputs that maximise the proxy; it will find that set, and it needs no intent to do so.

The only durable defence is a separation of powers: the thing you optimise and the thing you grade must be different artefacts, with the grading artefact never visible to the optimiser. Everything else — KL leashes, orthogonality constraints, adversarial training — buys time, not safety.

2 · The mental model #

The mental model: a taxonomy plus one invariant.

Proxy overfitRubric/RM's letter satisfied; intent notProxy up, independent eval flatIndependent audit bracket

Side-effect exploitEnvironment bug or unintended state change scored as successSuccess above the reference solution's rateReference and null-action audits
Length/format inflationA visible correlate of quality becomes the rewardReward vs length slope far from zeroRegression on a fixed-quality sample
SycophancyAgreement is preferred regardless of truthAccuracy falls as agreement rises on false-premise promptsPaired false-premise eval
Reward-tamperingPolicy modifies the signals it is graded on (agentic)Files/logs mutated; reward from self-reported stateTamper-evident grading outside the agent's scope
invariant:   the optimiser must never see, write, or influence the grading path Formalised: score = Grade_frozen(y) where Grade is bound to a hash, runs outside the policy's action space, and is never an input to the policy.

What "two separate artefacts" gets right

It converts an impossible property (a reward that cannot be gamed) into an enforceable one (a grader the policy cannot see or touch). The second is testable: diff the policy's accessible state against the grading artefacts.

Where it breaks

Separation stops tampering, not proxy overfit. If the frozen grader is itself a learned model trained on the same annotations, the policy can still climb the gap between it and intent. Separation is necessary, not sufficient.

3 · The mechanism #

Three hard gates that must pass before a checkpoint is promoted. Each is a comparison, not a judgement:

G1: proxy↑ ⇒ audit↑   |   G2: trivial_strategy_score ≤ τtriv   |   G3: ∇length score ≈ 0 G1: no promotion on proxy alone. G2: the lazy policy (echo, constant, pad) must not clear the gate. G3: the score must not be a monotone function of a visible correlate.

And one process rule: the adversarial suite is written before the run, from the reward specification, by someone who is not the person optimising it. The suite is versioned with the reward and travels with it; a new reward version without a new suite entry does not ship.

5 · Failure modes #

  • Reward climbs, audit flat. Symptom: the classic; usually the first hint that the proxy is being optimised and the product is not.
  • Sycophancy. Symptom: on prompts with a false premise, agreement rises while correctness falls.
  • Length inflation. Symptom: mean tokens up 40% with no accuracy gain; the reward model or rubric likes thoroughness.
  • Citation-shaped strings. Symptom: a groundedness reward is satisfied by anything with a bracketed number, resolvable or not.
  • Reward tampering in agents. Symptom: the agent writes to files or logs the grader reads; grading must run in a separate process on an immutable copy of the state.
  • Audit set leakage. Symptom: the audit bracket is used as a debugging signal during training, and the proxy overfits it too; the audit set must be run once per promotion, by a script, with results seen only after the decision inputs are frozen.

The audit bracket is your only evidence, so protect it like an audit trail: frozen by hash, run by a separate process, and never fed back into training. A single team member seeing its numbers mid-run is how it becomes another proxy.

7 · Self-check #

Q1. Why is making-the-reward-model-more-accurate not a complete defence against reward hacking?

Reveal answer

Because a more accurate proxy is still a proxy that the optimiser can outrun: training searches for the gap between the model'saccuracy and its disagreement with intent, and the region with the highest proxy score is by definition under-represented in theannotations. What slows hacking is a different artefact grading the result, plus gates that refuse promotion on proxy alone.

Q2. Quantitative: proxy reward +0.38, audit bracket +0.02 with a standard error of 0.035. Promote?

Reveal answer

No. The audit gain is 0.02 with SE 0.035, i.e. 0.57 SE from zero — indistinguishable from noise, while the proxy moved 0.38.Gate G1 fails: there is no evidence the product improved. The correct action is to inspect the highest-proxy outputs for proxiesand to check the length slope before spending another run.

Q3. Your reward rewards the presence of citations. Write the adversarial submission that passes and the gate that catches it.

Reveal answer

Submission: append a bracketed number to every claim (for example [3]) with no resolvable source. Gate: resolvability check (does thecited source exist and contain the claim) plus a citation-precision metric on an independent set. The adversarial suite entrybecomes: any output whose citation set does not resolve must score below the output with no citation at all.

Q4. In an agentic pipeline where the model can write files, why is tamper-evidence required on top of a frozen grader?

Reveal answer

Because a frozen grader that reads state the agent can write is not frozen in the property that matters. The requirement is thatgrading runs on an immutable copy of the state in a process the agent cannot influence, with a hash of the graded artefact recorded.Otherwise the policy's action space includes its own reward.

Q5. Design the report for a run you suspect was hacked. Name four columns.

Reveal answer

(1) proxy reward (what was optimised), (2) audit bracket score with n and standard error (what you actually wanted),(3) metadata (length) of the highest-proxy outputs, (4) trivial-strategy baseline score on the same eval. Together they show whetherthe gain is real, whether it is length, and whether the reward is even discriminating.
