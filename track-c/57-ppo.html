L57 · PPO for LLMs: clipping, the value model, the KL leash, four models

PPO costs four models and buys two things: a lower-variance advantage and a step size that cannot destroy the policy. This page runs the whole loop, deletes the critic to show what it was for, and states exactly where the clip stops helping.

~28 min difficulty ●●●●○ build: PPO vs GRPO tradeoff analysis
clipped surrogate probability ratio value model advantage baseline KL leash inner epochs trust region critic collapse

1 · Why it exists #

PPO (arXiv:1707.06347) exists because the naive policy gradient is a high-variance estimator wrapped in a fragile step size. Take one wrong step and the policy collapses into a degenerate generator — and with a language model you cannot detect the collapse until you have sampled a few thousand completions, by which time the checkpoint is ruined. The original problem PPO solved, in the 2017 RL sense, is: how do you take the largest step that is still safe, without solving a constrained optimisation at every update?

For LLMs the same problem acquires three extra bodies. The reward is a learned model that can be wrong; the "policy" has billions of parameters, so a large step is not a step but a teleport; and the thing you are trying to preserve (fluency, format, instruction-following) lives in a distribution you do not have a constraint for. PPO for LLMs therefore runs four models:

ModelJobCostWhat breaks if it is wrong
Policy πθGenerates and is trainedFull fwd+bwdNothing — this is the product
Reference πrefFrozen KL anchorForward onlyNo leash: drift into degenerate high-reward text
Reward model RφScores completionsForward onlyOptimises the wrong thing, confidently
Value model VψBaseline to cut advantage varianceForward + its own backwardNoisy advantages, and no error signal telling you so

PPO is a variance-reduction scheme with a trust region bolted on. The value model exists only to make the advantage estimate less noisy; the clip exists only to stop one noisy step from destroying the policy. Both are engineering, not science, and both are replaceable — which is exactly what lesson 56 does.

2 · The mental model #

The mental model: the policy gradient says "make sampled actions with above-average reward more likely". The problem is that "above average" requires knowing the average, and the naive estimator uses the raw reward, so everything with high reward looks good regardless of whether it is better than what you would have done anyway.

∇θJ = E[ (R − b) ∇θ log πθ(a|s) ] b is any baseline that does not depend on the sampled action. Var of the estimator falls as b approaches E[R]; the expectation is unchanged for every b.

PPO chooses b = Vψ(s), a learned prediction of expected reward. That is a whole extra network, and for an LLM it is asked to predict the eventual reward of a half-written answer from the tokens so far — a genuinely hard prediction whose errors then appear as advantage noise. The key numbers from the lab below: the baseline removes 97% of the raw reward's second moment in this toy, which is why PPO works at all, and also why the critic's own error matters so much.

What "the critic is a variance filter" gets right

It explains why anyone tolerates a fourth model: without it, the gradient is dominated by prompt difficulty. It also explains why the critic does not need to be accurate — only to correlate with the truth.

Where it breaks

Unbiasedness requires b not depend on the sampled action. A critic trained while the policy moves becomes correlated with the very samples it is supposed to debias, and then the estimator is biased and the bias has no error bar. This is the quiet failure PPO is famous for and the reason GRPO's empirical baseline is attractive.

3 · The mechanism #

The clipped surrogate, the KL leash, and the advantage — the three pieces that make PPO "PPO":

ρt = πθ(at|st) / πθold(at|st)
LCLIP = Et[ min( ρtÂt,  clip(ρt, 1−ε, 1+ε) Ât ) ]
objective = LCLIP − β KL(πθ ‖ πref)  (often also − c1·V-loss + c2·entropy) ρ compares the policy to the one that produced the samples. At the first inner epoch ρ = 1 exactly; it drifts at later epochs, which is when the clip can fire.

Three implementation facts that decide whether your PPO is real:

  • ρ must be recomputed against the stale sampling policy πθold, not against the reference. Using the reference as the denominator is the most common PPO bug that still trains.
  • KL is an estimate. In practice a low-variance per-token estimator is used rather than the full sequence KL; whichever you use, log it and gate on it.
  • Multiple inner epochs are the point. PPO's efficiency comes from reusing one batch for several optimiser steps — that is exactly what makes ρ drift and the clip necessary. One epoch per batch is leaving its main advantage on the floor.

The lab below is a complete PPO loop on a one-token bandit with all four models present, followed by a ratio sweep showing where the clip binds.

# L57: the PPO knife-edge, measured. Ratio is recomputed each inner epoch from the # stale sampling policy, exactly as a real implementation does. import math, random EPS, BETA_KL, LR, C_VAL, STEPS, INNER = 0.2, 0.02, 0.4, 0.5, 400, 1 PROMPTS, ACTIONS = 2, 2 REWARD = {0: [1.0, 0.0], 1: [1.0, 0.0]} # ground truth: action 0 correct for both prompts RM = {0: [0.9, 0.6], 1: [0.7, 0.55]} # learned reward model, imperfect, prompt-dependent def softmax(z): m = max(z) e = [math.exp(v - m) for v in z] s = sum(e) return [v / s for v in e] def kl(p, q): return sum(a * (math.log(a) - math.log(b)) for a, b in zip(p, q)) def train(use_value, seed=0): rng = random.Random(seed) pi = [[0.0] * ACTIONS for _ in range(PROMPTS)] ref = [softmax(p) for p in pi] # model #2: reference V = [0.0] * PROMPTS # model #4: value model kl_tr = [] for _ in range(STEPS): for s in range(PROMPTS): p_old = softmax(pi[s]) # sampling policy, frozen for this epoch a = rng.choices(range(ACTIONS), weights=p_old)[0] shaped = RM[s][a] - BETA_KL * kl(p_old, ref[s]) adv = shaped - (V[s] if use_value else 0.0) if use_value: V[s] += LR * C_VAL * (shaped - V[s]) for _ in range(INNER): p = softmax(pi[s]) ratio = p[a] / p_old[a] # the real ratio: new prob / stale prob surr = min(ratio * adv, min(max(ratio, 1 - EPS), 1 + EPS) * adv) for j in range(ACTIONS): # d log p(a)/d z_j = 1[a==j] - p_j ; /p[a] for the ratio logits_grad = (p[a] / p[a]) * ((1.0 if j == a else 0.0) - p[j]) pi[s][j] += LR * surr * logits_grad kl_tr.append(sum(kl(softmax(pi[s]), ref[s]) for s in range(PROMPTS)) / PROMPTS) return pi, kl_tr def graded(pi): return sum(sum(pk * REWARD[s][k] for k, pk in enumerate(softmax(pi[s]))) for s in range(PROMPTS)) / PROMPTS for label, use_v in (("policy+ref+RM+value", True), ("value model deleted", False)): pi, klt = train(use_v) print(f"{label:<26} graded={graded(pi):.3f} KL final={klt[-1]:.3f} KL last20={sum(klt[-20:]) / 20:.3f}") rng = random.Random(5) w = wo = 0.0 for _ in range(20000): s = rng.randrange(PROMPTS) a = rng.randrange(ACTIONS) w += (RM[s][a] - 0.5 * sum(RM[s])) ** 2 wo += RM[s][a] ** 2 print(f"\nmean squared advantage with critic {w / 20000:.4f}, without {wo / 20000:.4f}" f" -> baseline removes {1 - w / wo:.1%} of it") print("\nwhere the clip binds, as a probability, starting from p_old = 0.5:") for ratio in (0.5, 0.8, 1.0, 1.2, 1.5, 4.0): val = min(ratio, min(max(ratio, 1 - EPS), 1 + EPS)) print(f" ratio={ratio:>4.2f} p_new={0.5 * ratio:>4.2f} surrogate multiplier={val:.2f}")

4 · Your hands #

Three labs: run PPO with its four models, delete the critic to see what it was for, and sweep the ratio to watch the clip bind.

Experiment 1 — PPO with all four models, then with three

A one-token bandit where the reward model is a decent but imperfect approximation of a 0/1 grader. The loop keeps a frozen reference, applies the KL leash, trains a value model per prompt, and clips the ratio against the stale policy.

# L57 Lab 1: PPO for LLMs -- policy, reference, reward model, value model. stdlib only. # The "LLM" is a one-token bandit: prompt type -> action (concise-correct or verbose-wrong). import math, random EPS, BETA_KL, LR, C_VAL, STEPS = 0.2, 0.02, 0.4, 0.5, 400 PROMPTS, ACTIONS = 2, 2 REWARD = {0: [1.0, 0.0], 1: [1.0, 0.0]} # ground truth: action 0 is correct for both prompts RM = {0: [0.9, 0.6], 1: [0.7, 0.55]} # the learned reward model is imperfect and prompt-dependent def softmax(z): m = max(z) e = [math.exp(v - m) for v in z] s = sum(e) return [v / s for v in e] def kl(p, q): return sum(a * (math.log(a) - math.log(b)) for a, b in zip(p, q)) def train(use_value, seed=0): rng = random.Random(seed) pi = [[0.0] * ACTIONS for _ in range(PROMPTS)] ref = [softmax(p) for p in pi] # frozen reference (model #2) V = [0.0] * PROMPTS # value model (model #4) kl_trace = [] for _ in range(STEPS): for s in range(PROMPTS): p = softmax(pi[s]) a = rng.choices(range(ACTIONS), weights=p)[0] k = kl(p, ref[s]) shaped = RM[s][a] - mean_r) ** 2 var_without += r ** 2 print(f"\nmean squared advantage: with critic {var_with / 20000:.4f} without critic {var_without / 20000:.4f}") print(f"variance removed by the baseline: {1 - var_with / var_without:.1%}")

Both variants converge once the reward model and the leash are in place — the toy has only two actions, so a critic cannot earn its keep in final accuracy. What it earns is the last line: the baseline removes about 97% of the raw reward's second moment.

Experiment 3 — the four-model memory budget, in the browser console

Before you pick a batch size, compute the footprint. This runs on any page: F12, paste, enter.

const P = 7e9; // policy parameters const bytesPerParam = { bf16: 2, fp16: 2, fp8: 1 }; const GB = (n) => (n / 1e9).toFixed(1) + " GB"; for (const [prec, bpp] of Object.entries(bytesPerParam)) { const w = P * bpp; const rows = { "policy weights": w, "policy grads": w, "Adam m+v (fp32)": 2 * P * 4, "reference weights": w, "reward model (~same size)": w, "value model (~same size)": w, }; const total = Object.values(rows).reduce((a, b) => a + b, 0); console.log(prec, "static total:", GB(total), "before any activations"); }

The static total alone is already several times the weights. This is the arithmetic behind "PPO is expensive": four models means four weight sets, and the optimiser state is fp32 regardless of training precision. Delete the value model (GRPO) and you remove one weight set plus one gradient buffer, which is exactly the trade lesson 56 makes.

5 · Failure modes #

  • Critic collapse. Symptom: value loss plateaus at a large constant and advantages become nearly constant across samples in a batch — the critic is predicting the batch mean and the policy learns nothing from within-batch variation.
  • ρ computed against the reference. Symptom: clip fraction is high at the first inner epoch (it should be zero) and the policy learns to satisfy the KL term rather than the reward.
  • KL leash too loose. Symptom: proxy reward rises for many steps while the graded eval is flat, and completions lengthen. Too tight: the policy is pinned to the SFT model and nothing improves. Both are invisible without logging KL per step.
  • Reward-model exploitation. Symptom: reward reaches its ceiling while quality falls (lesson 75). PPO's clip does not protect against this at all; the trust region is in policy space, not in reward-model accuracy.
  • Four-model memory blow-up. Symptom: OOM at the batch size you planned, and a silent fallback to micro-batches that changes the effective learning rate. Budget memory before choosing the config, not after.
  • Entropy collapse. Symptom: completion diversity at a fixed prompt falls to near-deterministic early, then the policy cannot recover because the samples it needs are never drawn again.
  • Non-deterministic sampling not seeded. Symptom: two runs with identical config diverge; you cannot attribute a regression to the clip change you made. See lesson 94.

7 · Self-check #

Q1. Why is the value model's error less dangerous than the reward model's error in an LLM PPO run?

Reveal answer

The value model only enters through the baseline, and any action-independent baseline leaves the expected gradientunchanged; its error adds variance, which is measurable and visible in the value loss. The reward model defines theobjective: its error changes what is being maximised, and no amount of variance reduction fixes a wrong target.

Q2. Quantitative: p_old = 0.5, ε = 0.2, A > 0. At what value of p_new does the clip start to bind, and why does the surrogate stop at 1.2?

Reveal answer

ρ = p_new/0.5. It exceeds 1+ε = 1.2 when p_new > 0.6. Beyond that, clip(ρ)=1.2, and min(ρA, 1.2A) = 1.2A,so further increases in p_new give no gradient. That flat region is the trust region: it removes the incentive to overshooton a stale probability estimate.

Q3. You notice the clip fraction is 0.35 at the first inner epoch of every batch. What is wrong, and what should it be?

Reveal answer

At the first inner epoch the policy is exactly the sampling policy, so ρ = 1 for every token and the clip fraction must beexactly 0. A large value proves that ρ is being computed against a different model — almost always the reference — or thatthe sampling policy is not being snapshotted per batch. It is a single-line fix and a high-value regression test.

Q4. Diagnostic: PPO memory OOMs at the planned batch size. You halve the batch and keep the learning rate. Name two consequences that make the run not comparable to the previous one.

Reveal answer

(1) The advantage is estimated from half as many samples, so its variance roughly doubles — the same learning rate nowtakes noisier steps. (2) Per-step gradient noise changes the effective exploration, so the KL trajectory and clip fraction aredifferent. Both make the run a different experiment; either scale the learning rate or report the change explicitly.

Q5. Why does the clip not protect you from reward hacking, and what does?

Reveal answer

The clip constrains movement in policy space relative to a stale policy; it says nothing about whether the reward iscorrect. A policy that finds a degenerate high-reward string can reach it in many small clipped steps. What protects you isan independent audit bracket that the optimiser never sees, plus diagnostics like the reward-vs-length slope, checked atevery gate.
