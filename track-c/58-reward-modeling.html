L58 · Reward models: Bradley–Terry, calibration, and the argmax gap

The reward model is the only model in the stack whose errors get optimised against. This page fits one on 4000 pairs, measures the exact number of reward points an optimiser gains by choosing the wrong answer, and lists the three checks that gate it.

~27 min difficulty ●●●○○ build: a tiny Bradley-Terry reward model
Bradley-Terry pairwise likelihood reward calibration length halo argmax gap swap-order test ridge regularisation distribution shift

1 · Why it exists #

A reward model is the most consequential model in the pipeline and the only one whose errors are optimised against. Everything else in the stack predicts or generates; the reward model defines what "better" means, and then a policy gradient spends days finding the inputs it likes most. Two failures follow directly and are worth stating as the reason this lesson exists:

  • The reward model is a compressing approximation of your annotators, not of quality. If annotators used length as a proxy for effort, the reward model learns length, and RL discovers that a long answer scores better than the one a clinician would trust.
  • The reward model is trained on pairs the base policy produced. As the policy moves, it visits regions the reward model never saw, where its errors are largest — and that is exactly where the policy is being pushed.

A reward model is a Bradley–Terry logistic regression on pair preferences. Its quality is measured two ways: agreement with held-out pairs, and the gap between the argmax of the learned reward and the argmax of the true quality. RL optimises for the first; only the second determines whether you get a better product.

2 · The mental model #

The mental model: a Bradley–Terry model turns pairwise comparisons into scalar scores. Assuming each response has a latent score s and comparisons are noisy reads of the difference:

P(yw ≫ yl | x) = σ( sφ(x, yw) − sφ(x, yl) ) Only differences are identified: s is defined up to a per-prompt constant. That constraint is why the reward has no absolute scale and why normalisation matters.

Train it by minimising −Σ log σ(sw − sl) over your pairs. That is all "reward model training" means at the objective level; everything else is architecture and data.

What "a scorer" gets right

It separates the data problem (pairs) from the use problem (query a scalar). You can re-fit on new pairs without a policy; you can calibrate it; you can attack it in tests before RL does.

Where it breaks

A scorer that only sees differences is unanchored: shifting every score by a constant leaves the pair likelihood unchanged, so the model has arbitrary units. When RL maximises it, the only thing that stops the score growing forever is the KL leash — not the reward.

Three diagnostics decide whether you can ship it:

DiagnosticWhat it detectsGate
Held-out pair accuracyFit qualitySet the bar from annotator-to-annotator agreement, not from 100%
Swap-order accuracyPosition bias leaking into the scoresAccuracy must not move more than a point or two when A/B are swapped
Score vs length slope (fixed-quality sample)Verbosity hackingA strong positive slope means you have a length detector

And the one that is not a diagnostic but a fixture: the argmax gap. Enumerate or sample the highest-scoring outputs under the reward model and grade them with your true evaluator. If they beat every real answer on the reward and lose to it on quality, the reward model has told you exactly how it will be hacked.

3 · The mechanism #

The loss, written for a pairwise dataset, plus the gate arithmetic:

L(φ) = − E(x,yw,yl) [ log σ( sφ(x,yw) − sφ(x,yl) ) ]  +  λ‖φ‖² sφ is any scoring function (a transformer with a scalar head works). The ridge term stops the score from running away on separable pairs.

The lab below fits a Bradley–Terry reward on 4000 pairs generated by an annotator with a specific, knowable pathology: a length halo. The true quality function mildly penalises length. The annotator rewards it anyway. Then the script prints the argmax of the learned reward next to the argmax of true quality — the gap RL will drive into.

# L58: train a reward model the way RLHF does -- Bradley-Terry on pair preferences. # Pure stdlib. Four candidate answers per prompt type, 4000 preference pairs. import math, random rng = random.Random(4) CITE, LEN_PENALTY, HALO = 3.40, 1.00, 1.30 # true quality vs the annotator's length halo CANDS = { # (cited?, length in "sentences") "concise_cited": (1.0, 1.0), "verbose_cited": (1.0, 4.0), "concise_uncited": (0.0, 1.0), "verbose_uncited": (0.0, 4.0), } KINDS = list(CANDS) def true_score(k): c, l = CANDS[k] return CITE * c - LEN_PENALTY * (l - 1.0) def annotator(a, b): z = (true_score(a) - true_score(b)) + HALO * (CANDS[a][1] - CANDS[b][1]) return 1 if rng.random() < 1 / (1 + math.exp(-z)) else 0 pairs = [] for _ in range(4000): a, b = rng.choice(KINDS), rng.choice(KINDS) if a != b: pairs.append((a, b, annotator(a, b))) phi = lambda k: CANDS[k] # feature map w = [0.0, 0.0] LR = 0.6 for _ in range(300): g = [0.0, 0.0] for a, b, y in pairs: d = [phi(a)[i] - phi(b)[i] for i in range(2)] z = w[0] * d[0] + w[1] * d[1] p = 1 / (1 + math.exp(-z)) err = y - p # d(log-likelihood)/dz g[0] += err * d[0] g[1] += err * d[1] w[0] += LR * g[0] / len(pairs) w[1] += LR * g[1] / len(pairs) def rm(k): return w[0] * phi(k)[0] + w[1] * phi(k)[1] ok = 0 for a, b, y in pairs: d = [phi(a)[i] - phi(b)[i] for i in range(2)] ok += ((1 if w[0] * d[0] + w[1] * d[1] > 0 else 0) == y) print(f"fitted reward model : citation={w[0]:+.3f} length={w[1]:+.3f}") print(f"a perfect reward : citation={CITE:+.3f} length={-LEN_PENALTY:+.3f}") print(f"training-pair accuracy = {ok / len(pairs):.3f}\n") print(f"{'candidate':<18}{'RM score':>10}{'true score':>12}") for k in KINDS: print(f"{k:<18}{rm(k):>10.3f}{true_score(k):>12.3f}") best_rm = max(KINDS, key=rm) best_true = max(KINDS, key=true_score) print(f"\nargmax of the reward model: {best_rm} (RM={rm(best_rm):+.3f}, true={true_score(best_rm):+.3f})") print(f"argmax of true quality : {best_true} (RM={rm(best_true):+.3f}, true={true_score(best_true):+.3f})") print(f"an RL optimiser gains {rm(best_rm) - rm(best_true):.3f} RM points by choosing the wrong answer.")

4 · Your hands #

Three labs. Fit the reward model and find the argmax gap; calibrate it; then run the adversarial test that belongs in CI next to every reward model.

Experiment 1 — fit the reward model, then find the argmax gap

Four candidate answers described by two properties: cited / uncited, short / verbose. True quality mildly penalises length; the annotator is generous toward it. The Bradley-Terry fit sees only the pair outcomes.

The fit recovers citation strongly and assigns length a POSITIVE weight even though true quality penalises it. The script prints the gap: the RL optimiser gains about 0.96 reward points for choosing an answer whose true quality is 3 points worse. That number is the hacking budget, quantified before any RL run.

Experiment 2 — calibrate: accuracy is not the metric that matters

Change one line — remove the length halo from the annotator (HALO = 0.0) — and re-run.

# in s58a.py, change CITE, LEN_PENALTY, HALO = 3.40, 1.00, 1.30 # to CITE, LEN_PENALTY, HALO = 3.40, 1.00, 0.00

The fitted length weight drops toward the true negative value and the argmax gap closes. This is the falsifier for the whole lesson: if the pathology is in the annotation, removing it from the annotation removes it from the reward model. If the gap persists with a clean annotator, the model or feature set is at fault, not the data.

Experiment 3 — the swap-order test in four lines

Position bias is the cheapest reward-model bug to detect and the most common. Run this against your own scorer.

pairs = [("A text", "B text"), ("C text", "D text")] # your held-out pairs scorer = lambda pair: (0, 0) # returns (score_left, score_right) flips = sum(1 for a, b in pairs if (lambda l, r: (l > r) != (r > l))(scorer((a, b))[0], scorer((a, b))[1]) and not True) # the invariant: scoring must be ORDER-FREE. If your API takes the pair, change it to score # each response independently -- a pair-aware scorer has no defined swap behaviour at all. print("order-free by construction" if scorer(("x", "x"))[0] == scorer(("x", "x"))[1] else "LEAK")

The real test is stronger than this sketch: score each response independently, compare, then compare again with the" " arguments reversed. Any disagreement is position leakage. If your scorer cannot be called on a single response, that is itself the" " finding.

5 · Failure modes #

  • Reward is a length detector. Symptom: regression of score on length, for fixed-quality samples, has R² above about 0.3. Everything downstream gets longer.
  • Distribution shift between pairs and policy. Symptom: held-out pair accuracy is 0.80, but the reward on the current policy's outputs has much higher variance than on the dataset's responses. The policy has left the support of the training pairs.
  • Calibration drift across prompts. Symptom: the same model scores much higher on easy prompts than hard ones, so RL prefers easy prompts; error attribution looks like "it got better at what it already knew".
  • Ridge/scale missing. Symptom: reward values grow without bound during RL; the KL term is the only thing stopping them and the run becomes a tug-of-war between two hyperparameters.
  • Pair source contamination. Symptom: pair accuracy near 1.0 that does not transfer — the pairs were produced by a model whose idiosyncrasies the RM memorised (e.g. scores by format rather than content).
  • Reward model sharing the policy's blind spots. Symptom: RM benefits from the same hallucinated citations the policy produces, so both agree and both are wrong; only an independent grader sees it.

Ship a reward model only with: a held-out pair set frozen by hash, a swap-order test, a score-vs-length regression on a fixed-quality sample, and a written list of the top-5 highest-scoring outputs with their true grades. Those five highest-scoring outputs are the attack surface; if you have not looked at them, you have not looked at the model.

7 · Self-check #

Q1. Why is a Bradley-Terry reward model only identified up to a per-prompt constant, and what breaks if you forget?

Reveal answer

The likelihood depends only on score differences between two responses to the same prompt, so adding anyprompt-level constant leaves every probability unchanged. Consequences: (1) the reward's absolute units are arbitrary,so comparing rewards across prompts is meaningless and an optimiser that averages them learns promptdifficulty; (2) unbounded growth during RL is a scale problem, not a signal problem, and needs normalisation or a ridge term.

Q2. Quantitative: the fitted weights are citation +3.35 and length +0.32, and true quality is citation +3.40 with length −1.00. By how much does an RL optimiser gain by choosing a verbose cited answer over the concise one?

Reveal answer

verbose_cited scores 3.35 × 1 + 0.32 × 4 = 4.62; concise_cited scores 3.35 + 0.32 = 3.67. The reward gain is 0.95.True quality: verbose 3.40 − 3.00 = 0.40 versus concise 3.40. So the optimiser gains about a full reward unit for a3-point drop in true quality. That single number is the reward-hacking budget.

Q3. Held-out pair accuracy is 0.78 while two annotators agree on 0.72 of their pairs. Is the reward model good?

Reveal answer

Roughly yes, and the number to compare against is annotator agreement, not 1.0: two humans disagree on28% of pairs, so the ceiling is about 0.72. Chasing accuracy above the human ceiling means fitting annotator noise. Break accuracy down by pairdifficulty band and by annotator: a model that agrees with one annotator far more than the others has learned thatperson, not the task.

Q4. Diagnostic: reward rises during RL, mean length rises, graded accuracy is flat. Give the exact regression you run and the value that indicts the reward model.

Reveal answer

Fix a difficulty band (same prompts, same true-score bucket), sample many responses, and regress the reward model'sscore on log-length. If the coefficient is positive with R² above roughly 0.3, the reward model is a length detectorand RL is doing exactly what you asked. The fix is upstream — length-balanced pairs and a rubric that definescompleteness — not a length penalty bolted onto RL.

Q5. Why does the reward model get worse exactly where the policy moves?

Reveal answer

Because it was fit on the base policy's output distribution, and the Bradley-Terry fit is only accurate insidethat support. RL pushes the policy toward the reward's high-score region, which is typically under-represented in thepairs — so the region it explores is precisely the region the reward model extrapolates worst. This is whyiterated retraining of the reward on fresh pairs is a common practical remedy.
