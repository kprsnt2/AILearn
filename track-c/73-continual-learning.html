L73 · Continual learning and forgetting during post-training

Every stage that improves its own metric can silently overwrite a capability from two stages ago. This page measures forgetting per capability, prices replay, and builds the gate that refuses the checkpoint instead of documenting the loss later.

~25 min difficulty ●●○○○ build: measure forgetting
catastrophic forgetting capability probes replay adapters capability floor probe contamination stage order regression gate

1 · Why it exists #

You fine-tune a model to be excellent at client-specific reporting. Two weeks later it cannot summarise a transcript it used to summarise well. Nothing was deleted, no data was corrupted — the gradient simply overwrote the weights that supported the old behaviour, because that is what gradient descent does when the new data is narrow. The failure is catastrophic forgetting in post-training, and in a multi-stage pipeline it is nearly invisible: every stage's gate measured its own target behaviour, and nobody measured the behaviour from two stages ago.

It gets worse in the multi-stage case. Stage 3's SFT can degrade stage 1's capability; stage 4's RL can degrade stage 3's format; and if the final model is compared only to the base, all the intermediate regressions average out into a number that looks acceptable.

Forgetting is measurable and therefore manageable. The instrument is a frozen probe set per capability, evaluated after every stage against the previous checkpoint and against the base. A pipeline that cannot name what it forgot is not a pipeline; it is a sequence of unrelated fine-tunes.

2 · The mental model #

The mental model: the weights are a shared resource. Training on distribution B moves the parameters toward better behaviour on B, and the movement is not constrained to the subspace that B needs. Where B's gradient is large, A's capability — which occupies the same parameters — degrades.

forgettingA = accA( θbefore ) − accA( θafter ),    for each capability A Measure per capability on a frozen probe set. Positive values are forgetting; a capability whose accuracy falls 5 points is a regression, whatever the new task gained.

What "shared resource" gets right

It predicts the main empirical pattern: forgetting scales with how far you train and how narrow the data is, not with model size. It also explains why replay works so well — it restores the competing gradient.

Where it breaks

Some apparent forgetting is not forgetting: the prompt distribution or the chat template changed, and the capability is intact but unreachable. Before you attribute a drop to training, re-run the probe through the exact serving path.

3 · The mechanism #

The gate arithmetic, per capability, with a tolerance that must be written before the run:

pass  ⇔  ∀ A ∈ capabilities:   accA(after) ≥ accA(base) − τA   and   ΔaccA ≥ −2·SEA τ is your tolerance per capability (0 for safety-critical probes). The second term keeps you from chasing noise: a drop within two standard errors is not evidence.

Two rules for the probe set:

  • One probe per capability, small and frozen. Thirty items per capability is enough to catch a 10-point regression and cheap enough to run after every checkpoint.
  • Probes are protected from every training stage. If a probe item appears in any stage's data, it is not a probe. Hash the probe set and diff it against every data file (lesson 74).

A capability survives if the pressure is small.""" pressure = (1.0 - replay_share) * gap return max(0.0, pressure) print("\nreplay share needed to keep each capability's drop under its tolerance:") for c in CAPABILITIES: # worst observed gap for that capability gap = max(0.0, BASE[c] - min(acc[c] for _, acc in STAGES)) need = 1.0 - TOLERANCE[c] / gap if gap > TOLERANCE[c] else 0.0 print(f" {c:<15} worst drop {gap:.3f} -> replay share >= {need:.2f}") print("\nread it as a floor, not a recipe: replay reduces the competing gradient, so the") print("share must be high enough that the old capability is not outnumbered in every batch.")

Experiment 3 — probe integrity check

A probe that appears in training data stops being a probe. Hash it and diff it against every stage file.

import hashlib, json def h(p): return hashlib.sha256(open(p, "rb").read()).hexdigest() probe_hashes = {h("probes/arithmetic.jsonl")} # one hash per capability probe for stage_file in ["data/sft.jsonl", "data/prefs.jsonl", "data/rl_prompts.jsonl"]: for line in open(stage_file): item = json.loads(line) if hashlib.sha256(json.dumps(item, sort_keys=True).encode()).hexdigest() in probe_hashes: raise SystemExit("PROBE LEAK into " + stage_file) print("probe integrity ok")

Run this in data CI so it fails the build, not in the training script. The failure it prevents looks like success:" " probe accuracy rising across stages, read as capability improvement and actually memorisation.

5 · Failure modes #

  • Silent capability regression. Symptom: a stage's own metric improves while an unrelated probe drops 5+ points; only a per-capability table shows it.
  • Probe contamination. Symptom: probe accuracy climbs when it should be flat — the probe leaked into training data.
  • Template-induced "forgetting". Symptom: the probe fails in serving but passes in the training harness; diff the token stream first.
  • Replay ratio too low. Symptom: forgetting shrinks but does not stop; the old data is outnumbered by an order of magnitude.
  • Adapter merge conflicts. Symptom: after merging two adapters, both capabilities are worse than either alone; test merged behaviour, not each adapter.
  • Stage-order erosion. Symptom: final model refuses to answer in the format stage 1 taught, because stage 3's data used a different format. Format is a capability; probe it.

The forgetting table (capability × stage, with base as the reference) belongs in the release record next to the accuracy gains. It is the artefact that makes "we improved the model" a claim about a tradeoff rather than a claim about one number.

7 · Self-check #

Q1. Three capabilities, base accuracies 0.82/0.74/0.91, after stage 2 they are 0.81/0.63/0.90. One tolerance is 0.02 and one probe is safety-critical. What does the gate say?

Reveal answer

Deltas are −0.01, −0.11, −0.01. Capability 2 is 11 points down, far beyond a 2-point tolerance, so the gate blocksregardless of stage 2's own improvement. The other two are within tolerance. This is why the gate must be per-capability: anaverage would have shown a 4-point drop and might have been rationalised.

Q2. Why is replay usually more effective than lowering the learning rate for preventing forgetting?

Reveal answer

A lower learning rate slows all movement, including the movement you want, and buys only a proportional reduction inforgetting. Replay changes the gradient itself: the batch contains examples of the old capability, so the update improves thenew task while keeping the old one's loss low. It is a different optimisation problem, not the same one run more gently.

Q3. Quantitative: stage 2 data is 20,000 examples, replay needs to be roughly 20% of each batch. How many stage-1 examples are in a 32-example batch, and what if the old data is unavailable?

Reveal answer

About 6.4 (round to 6 or 7) stage-1 examples per batch. If old data is unavailable, options are generating pseudo-replay fromthe previous checkpoint (sample outputs from it and train on those), or freezing parts of the model (adapters), or accepting andmeasuring the loss. Each is a different tradeoff; none is free.

Q4. Diagnostic: probe accuracy falls in serving but not in the training harness. Give the three checks in order.

Reveal answer

(1) Chat template / token stream diff between harness and serving. (2) Sampler settings (temperature, stop sequences) differ, sothe probe's output format changes and the parser fails. (3) The serving model is a different artefact — quantised, merged, or astale checkpoint. All three are configuration; none requires retraining, which is why they are checked first.

Q5. Why must a probe set be hashed and diffed against training data?

Reveal answer

Because a probe that appears in training becomes a memorisation test, and its accuracy rises instead of reflecting thecapability. The hash lets you prove, per run, that the probe was not trained on; the diff is the mechanism. Without both, agreen probe table is not evidence of anything.
