L46 · Alternatives: State-Space Models, RWKV, and Hybrid Attention

Attention keeps every past token so it can look back arbitrarily. A state-space model keeps a fixed-size summary instead — 8 MiB per sequence whatever the context. The cost is exact recall, and no amount of engineering has made a fixed state retrieve a specific token as well as a cache can.

1 · Why it exists #

Attention's defining cost is that its memory grows with everything it has read. With MLA's compressed cache at 70,272 bytes per token (L33), a 128k-token sequence needs 8.58 GiB of state, and 1M tokens needs 65.45 GiB. That state must be held for every concurrent sequence and re-read on every generated token. The two terms compound: concurrency is memory, and speed is bandwidth.

This is a strange design if you think about it as an information problem. The model does not need every past token to answer every question — most of the time it needs a summary: what has been discussed, what constraints apply, what entities exist. A recurrent model makes that explicit: it maintains a fixed-size state vector that it updates at each step, so memory is constant in context and per-token work is constant in context.

The failure that motivates real interest: at long context, attention costs are dominated by memory, not by the quality of the reasoning. If you could get attention-class quality with constant state, long context would become nearly free. The empirical answer so far is the hybrid: use recurrent layers for most of the stack and attention for a minority, which captures most of the memory win while keeping exact recall where it matters.

Attention trades memory for exact recall. Recurrence trades exact recall for constant memory. Hybrids buy most of the memory win and pay only a small recall penalty — and knowing which layers need attention is the whole design question.

2 · The mental model #

Analogy (labelled): a meeting. Attention is a full transcript: you can look up the exact sentence anyone said at any time. A state-space model is the note-taker's notebook: a fixed number of pages, continuously updated, summarising what matters. The notebook is cheap and always the same size; it cannot quote verbatim.

What the analogy gets right

Fixed cost, constant update work, no growth with meeting length. It also gets the quality profile right: summary-level questions are fine, exact-recall questions are not.

Where it breaks

A notebook is lossy in an uncontrolled way. A selective SSM learns what to write, and the state is a wide vector (thousands of channels), so it is a very capable notebook — but its capacity is fixed and provably cannot do exact associative recall of an unbounded number of pairs. The failure is capacity, not compression quality.

3 · The mechanism #

ht = Āt ht−1 + B̄t xt   ,   yt = Ct ht xt is the input, ht the state, yt the output. The key word is selective: Ā, B̄ and C are functions of the input, so the model can choose to forget, store, or read at each step. A non-selective linear SSM is a fixed linear filter and cannot do content-based decisions at all.

Why "selective" is the whole idea

A plain linear state-space layer computes a fixed convolution: the same decay pattern regardless of content. It is fast (FFT/scan-able) but cannot decide “keep this fact, discard this filler.” A selective (input-dependent) SSM can, and the price is that it can no longer be computed as a convolution — it must be scanned sequentially, which is why efficient parallel scan kernels (in the same lineage as L39) were the enabling engineering.

Why a fixed state cannot do exact recall

This is the argument you should be able to make in one paragraph. Suppose the model stores m key–value pairs in the state and must retrieve one. A recurrent state of dimension s can distinguish at most s independent real numbers; storing m arbitrary vectors requires capacity scaling with m. With m unbounded and s fixed, the state must lose information — there is no trick that avoids it. Attention does not have this problem because it stores everything and pays to read it.

RWKV: a different lineage, same trade

RWKV is a linear-attention-like recurrence (the WKV operator) designed for the same reason: training parallelisable, inference with constant state and O(1) per-token work. Its lineage is different (a token-shift time-mix and channel-mix block structure) but the economics are identical to the SSM case, and the same recall limitation applies in its pure form.

Why production uses hybrids

The practical result that matters: a stack that is mostly recurrent layers with a minority of attention layers retains most of the long-context quality of full attention, while the state stays dominated by the recurrent layers. If 3 in 4 layers are recurrent, cache size falls roughly 4× while attention still supplies exact recall at 1 in 4 layers.

That is the same economic shape as MLA (compress the cache) and DSA (read less of it) — three independent attacks on the same bill, and they compose. The design question in 2026 state as of 2026-10 is not “attention or SSM” but “what attention-to-recurrence ratio, at what depths.”

Evaluate hybrids on two axes separately: memory/throughput (state bytes, decode step time at 128k) and recall (needle-in-a-haystack with many needles, exact-copy tasks, multi-hop lookup). A hybrid that wins the first and loses the second is a different product, not a better one. Reporting one number hides the trade you are making.

4 · Your hands #

Experiment 1 — state bytes versus context, for each architecture

The comparison that decides deployments. Sweep context length and print the state for attention, pure recurrence, and a hybrid.

def attn_state(ctx, tok_bytes=70272): return ctx * tok_bytes def ssm_state(layers, d_inner=4096, d_state=16): return layers * d_inner * d_state * 2 def hybrid_state(ctx, n_attn_layers, n_ssm_layers, tok_bytes=70272): return n_attn_layers * ctx * tok_bytes + ssm_state(n_ssm_layers) print("ctx pure-attention pure-SSM 3:1 hybrid") for ctx in (4096, 32768, 131072, 1_000_000): print(f"{ctx:>8,} {attn_state(ctx)/1024**2:12.1f} MiB {ssm_state(64)/1024**2:10.1f} MiB " f"{hybrid_state(ctx,16,48)/1024**2:12.1f} MiB")

Pure attention: 0.27 GiB at 4k rising to 65.45 GiB at 1M. Pure SSM: 8.0 MiB flat. A 3:1 hybrid (16 attention layers of 64): 0.57 GiB at 32k, 2.26 GiB at 128k, 17.17 GiB at 1M — a 3.8× reduction versus full attention's 8.58 GiB at 128k, exactly as the 16/61 layer ratio predicts. What to notice: the hybrid is not constant, it is attention divided by 4. Its memory still grows; it just grows slower.

Experiment 2 — simulate the recall failure, not just the cost

The claim that a fixed-size state loses exact recall is testable in fifteen lines: store key–value pairs into a fixed d×d associative state and measure how faithfully you can read each value back. Recall quality should fall as the number of stored pairs approaches the state dimension — that is the capacity limit, made visible.

import numpy as np def recall_quality(n_pairs, d=64, seed=46): rng = np.random.default_rng(seed) K = rng.normal(0, 1, (n_pairs, d)); V = rng.normal(0, 1, (n_pairs, d)) M = V.T @ K # fixed-size d x d state, written once per pair cos = [] for i in range(n_pairs): r = M @ K[i] # read with the key cos.append(r @ V[i] / (np.linalg.norm(r) * np.linalg.norm(V[i]) + 1e-9)) return np.mean(cos) for d in (64, 256): print(f"d_state={d}", [round(recall_quality(n, d), 3) for n in (2,8,32,128,256)])

Measured (cosine of read-out with the true value, at n = 2 / 8 / 32 / 128 / 256 pairs): d = 64 → 0.985 / 0.952 / 0.826 / 0.574 / 0.431; d = 256 → 0.995 / 0.984 / 0.942 / 0.819 / 0.709. The curve is monotone in both directions: more pairs degrade recall, more state dimension recovers it. Attention does not have this curve — storing all n keys retrieves each exactly regardless of n. That difference, not the memory saving, is the architectural trade. Falsification: if recall at 256 pairs equals recall at 2, your state is effectively larger than d×d — check that M is not being rebuilt per pair.

Experiment 3 — the crossover context length

At what context does the recurrent state become the smaller option? Below it, attention is strictly better on both axes (memory and recall). This is the line that decides whether a hybrid is worth its complexity.

python -c " ssm=64*4096*16*2; tok=70272 print('SSM state bytes:', ssm, '=', ssm/1024/1024, 'MiB') print('crossover at', ssm/tok, 'tokens of attention cache') for ctx in (64,128,256,1024,4096): print(f' ctx={ctx:5d}: attention {ctx*tok/1024:.0f} KiB vs SSM {ssm/1024:.0f} KiB') "

Crossover at 119 tokens. So for any realistic prompt, the recurrent state is already 10× smaller at 1,024 tokens and 1,000,000× smaller at 1M. That is the entire attraction — and the reason the fair comparison is never “which is better” but “how many attention layers do I need to keep exact recall, and where must they sit?”

5 · Failure modes #

  • Recall benchmark passes on synthetic needles. Symptom: needle-in-a-haystack scores look fine but multi-hop and exact-copy tasks fail on real documents. Synthetic needles are low-interference; real text is full of distractors that compete for state capacity.
  • Comparing against a weak attention baseline. Symptom: the hybrid matches “attention” while the baseline was a short-context config that never had to retrieve anything. Compare on a retrieval-heavy suite.
  • Assuming constant memory means constant cost. Symptom: decode step time still grows with context even though state is fixed — the recurrent scan is sequential, so per-token latency has a floor set by sequential depth, not bandwidth.
  • Hybrid ratio chosen by memory alone. Symptom: memory target met and quality regressed on the one task type you did not test. The attention layers must be placed where retrieval is needed; uniform interleaving is a design starting point, not an optimum.
  • Tooling gap treated as quality gap. Symptom: the alternative architecture “performs worse” because kernels, fusion and quantization support lagged. Re-evaluate after the kernel work, not before.

7 · Self-check #

Q1. A 64-layer SSM with dinner = 4096 and dstate = 16, bf16. What is the state size per sequence, and at what attention context length is it equal to an MLA cache at 70,272 B/token?

Reveal answer

Per layer: 4096 × 16 × 2 = 131,072 B = 128 KiB. Over 64 layers = 8,388,608 B = 8,192 KiB = 8 MiB. Crossover: 8,388,608 / 70,272 = 119.4 tokens. Past 120 tokens the recurrent state is smaller, and the gap widens linearly with context.

Q2. A hybrid uses 16 attention layers and 48 recurrent layers of 64. What is the state at 128k tokens, and how does it compare with full attention?

Reveal answer

Attention part: 16 × 131,072 × 70,272 = 1.474×1011 B = 137.2 GiB? Careful — the attention cache is per token, so 16 layers × 131,072 tokens × (70,272/61 bytes per layer per token). Per-layer per-token is 70,272/61 = 1,152 B. So 16 × 131,072 × 1,152 = 2.415×109 B = 2.25 GiB. Recurrent part: 48 × 128 KiB = 6 MiB. Total ≈ 2.25 GiB versus 8.58 GiB for full attention — a 3.8× reduction, matching the 16/61 layer ratio.

Q3. Why can a fixed-size state not perform exact recall of an unbounded number of key–value pairs, stated as a capacity argument rather than an empirical one?

Reveal answer

A state of dimension s holds at most s independent real values, so the set of distinguishable states has s degrees of freedom. Retrieving m arbitrary, independent key–value pairs requires information that scales with m; once m exceeds the state's effective capacity, distinct pair-sets map to (nearly) the same state, so the read-out cannot separate them. Attention avoids this by storing m entries and paying O(context) read cost — it is a memory-for-recall trade, not a smarter algorithm.

Q4. Diagnostic: a hybrid model matches full attention on average benchmark scores and fails on multi-hop document QA. What do you check first?

Reveal answer

Where the attention layers sit relative to where retrieval happens. If all attention layers are early and the later layers are purely recurrent, the information retrieved early must survive many recurrent updates before being used — it gets overwritten. Check per-layer probe accuracy for the retrieval target, and test a configuration with attention layers closer to the output or more evenly distributed.

Q5. MLA, DSA, and hybrids all reduce long-context cost. Are they substitutes or complements, and what does each actually attack?

Reveal answer

Complements, on three different terms. MLA shrinks the bytes stored per token per layer (constant factor, lossless until the rank cap). DSA reduces the number of positions read per query (asymptotics of the read). A hybrid replaces some layers entirely with constant-state recurrence (removes the growth for those layers). A model can use all three, and the savings multiply rather than overlap — which is why the 2026 frontier stack looks like "MLA + sparse selection + some recurrent or compressed layers" rather than one winning mechanism.
