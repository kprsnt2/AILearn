PART TWO · THE DISCOVERY PROGRAM

SKILLA: autonomy you can audit, discovery you can check.

Everyone is racing to make agents do more on their own. Almost nobody is racing to make the result checkable. That is the opening. This is a design for closing the two gaps that separate today's best swarms from something that deserves the word "autonomous" — the ability to choose its own work, and the ability to prove the work was real to someone who does not trust it.

The frontier is not "a bigger agent loop." It is a skill library with falsification pressure, and authority that is earned rather than declared. An agent that cannot lose authority cannot learn to deserve it.

01 Why this is still unsolved

Not the hype version. The engineering version.

Look at what a good production agent actually is in 2026. It is a prompt loop around a model with tools, a budget, and some guardrails. It is genuinely useful. And it has four hard ceilings, none of which is fixed by a better model:

CeilingWhat actually happensStatus
The work is chosen for it A human writes the task, the success criteria, and the stopping rule. The agent optimises inside that box. It never asks whether the box contains the right work. OPEN
Success is a declaration The agent says it is done. The ledger records that it said so. A stranger reading the ledger must take the agent's word for the outcome. PARTLY SOLVED by independent oracles
Competence does not transfer Something learned in run 40 is not systematically available in run 41. Each run is a fresh model with a fresh context. The swarm re-learns the same lessons. OPEN
Cost grows with ambition, not with value Longer runs cost more because they are longer, not because they produce proportionally more verified value. There is no price signal on effort. PARTLY SOLVED by budgets, not by economics

The fourth one is a hint. Most agent systems have a budget — a hard cap on tokens or dollars. Almost none have a price — a way to say that this line of work is worth more than that one, and to make the agent behave differently because of it. Budgets stop overspend. Prices allocate effort. Only one of those produces intelligent behaviour.

The strategic claim: the reliability stack is a competitive moat that everyone else treats as overhead. 7+ years of designing audits that survive federal review is not a soft skill in this field — it is the scarce input. The teams that win the next phase are the ones who can run an unattended system and still say, with evidence, precisely what it did and did not prove.

02 The two gaps, stated precisely

If you cannot state a gap in a way that could be measured, it is not a research problem.

Gap A — Bidirectional alignment. Current agents align upward: a human gives a goal, the agent acts. The missing direction is downward and sideways: the agent proposes what is worth doing, argues for it against alternatives with evidence, and accepts that its proposal may be rejected by a test rather than by an authority. Today the agent's initiative is limited to "retry" and "try another approach to the same task." It never says "this task is the wrong task."

Gap B — Trustless capability. An agent's competence is currently proven by demonstration inside a trusted harness. The missing thing is competence that survives an adversarial reader. If I hand you a ledger and say "this agent learned X," you should be able to falsify that claim from the ledger alone, without running the agent, without trusting its authors, and without trusting the agent.

Both gaps share one root cause: there is no object in the system that can be falsified. Prompts cannot be falsified. Loops cannot be falsified. Goal statements cannot be falsified. A skill with a validity condition and a measured hit rate can be falsified. That is the object to build the system around.

03 The design: four components

SKILLA = Skill Library + Ledger + Authority + Auction. Each is small enough to build alone.

1 · The living skill library

A skill is not a markdown file. It is an assertion with teeth. Minimum schema:

{ "id": "s_0042", "claim": "For CLI-agent test suites, a 2-model arbiter with both verdicts positive rejects fabricated PASS claims at rate >= 0.95 on seeded cases.", "validity_condition": "CLI agents, < 200 tool calls per run, arithmetic and filesystem tasks; NOT valid for tasks where ground truth is subjective.", "evidence": { "method": "seeded_failure_injection", "n_trials": 140, "hits": 133, "hit_rate": 0.950, "ci95": [0.902, 0.977], "replication_runs": ["run_881", "run_902"], "independent_oracle": "oracle_v3" }, "fail_card": { "last_invalidated_by": "run_917", "deviation_sigma": 2.6, "note": "model served at 1M ctx, hallucinated step refs at 3x baseline" }, "lineage": ["s_0011", "s_0019"], "authority_effect": {"max_autonomy": 0.72, "allowed_actions": ["..."]} }

Four rules make the library living rather than a wiki:

  • Every claim needs a validity condition. A skill with no boundary is a rumor. The boundary is what makes it falsifiable.
  • Every skill is periodically re-tested. Skills are sampled at random each cycle and re-run. A skill's hit rate is a computed quantity with a confidence interval, not a stored number that gets stale.
  • Deviation above 2σ forces a demotion. If a re-test lands more than two standard deviations below the recorded hit rate, the skill is not "updated" silently — it is flagged, its authority shrinks, and the failure becomes a new research task on the frontier.
  • Failure cards are first-class. The most valuable entry in the library is not a skill that works; it is an accurately recorded reason that a skill stopped working. That is the object no current agent system keeps well.

2 · The frontier, not the backlog

The agent's self-directed work comes from a frontier — the boundary of the library where claims have thin evidence (low n_trials or wide CIs). This is the crucial inversion: a normal agent is told what to do; this agent is told where it is least certain, and choosing the work means choosing which uncertainty to attack next. That is measurable, and it is exactly what the loop above closes.

3 · The auction (this is the unusual part)

Each cycle, candidate jobs (re-tests, frontier probes, new-skill proposals, replications) bid for a fixed compute escrow. The bid is not a number the model makes up — it is a stake. A job that fails to reproduce its claimed improvement pays the stake back from the agent's budget. A job that reproduces it keeps the stake and earns a larger allocation next cycle.

Why this matters: it converts the agent's enthusiasm into a number it can lose. A model that always claims success is quickly and mechanically poor. No reward-hacking needed — the economics do the filtering.

4 · The audit layer

The hash-chained ledger — already built and proven in your AgentSwarm work — is extended so that it records claims, not just events. Each cycle produces an evidence bundle: the job manifest, the exact model/version/harness config, the action log, the oracle verdicts, the cost and latency attribution, and the hash chain over all of it. A stranger can verify the bundle without trusting the agent: recompute the chain, re-run the oracle on the recorded artifacts, and check the arithmetic on every score.

04 The authority formula

The core idea: autonomy is not granted to an agent, it is earned per skill and it decays.

This is the concrete mechanism that turns "trust" from a vibe into a computation. Let each skill s carry a track record. Then define:

A(s) = wr·logistic(λ·(r̂s − r0)) · wc·min(1, ns/n0) · e−μ·ages · (1 − ρs) A(s) = authority ∈ [0,1] granted to actions justified by skill s. r̂s = measured hit rate (lower bound of CI), r0 = the floor rate the org requires. ns = evidence count, n0 = evidence needed for full credit. ages = cycles since last re-test. ρs = observed reward-hacking rate (claims that failed independent replication).

Every term is doing real work:

  • logistic(r̂ − r0) — an agent at exactly the floor gets 0.5 authority, an agent far above it approaches 1 (with diminishing returns), an agent below gets almost nothing. Using the lower bound of the confidence interval, not the point estimate, means small samples cannot buy authority.
  • min(1, n/n0) — no authority on a single lucky run. This is the "n≥100" rule from auditing, in formula form.
  • e−μ·age — asymmetric decay. An untested skill silently loses authority. This is the direct attack on state drift.
  • (1 − ρs) — self-reporting of internal failures is rewarded, because not reporting them drains authority when the oracle finds them. You cannot lie your way up.

What authority buys — the ladder

A(s)The agent may…Control
0.00 – 0.25read, plan, propose at the frontier. Nothing that mutates state.human reads every output
0.25 – 0.50run the proposed job in an isolated sandbox, any sandbox, no external side effects.sandbox

Read that ladder again. The last rung is the interesting one. It is the point where the agent, not the human, decides what is worth doing — but only for the specific subproblems where it has beaten a hard test more than ~100 times and stayed above the floor while decaying. The design deliberately stops there rather than granting the whole system a fixed autonomy level.

05 The discovery protocol

The part that makes it "research" rather than "automation with extra steps."

A run that succeeds is not a discovery. A run that narrows uncertainty with a falsifiable claim is. So every cycle must produce at least one of these, and the type is recorded:

EXPANSION

A new skill enters the library with a validity condition and a measured hit rate over at least n0 trials. Cost: low. Value: low until it survives a deviation test.

EXPLORATION

A frontier probe that turns "we don't know" into a number. Even a failed probe is a success if the uncertainty is now bounded.

REPLICATION

An independent re-run of an existing skill on a fresh agent instance. The only evidence that counts toward confidence.

FALSIFICATION

A skill's validity condition is shown to be too broad. Highest value per unit cost — this is the only type that removes the swarm's accumulated drift.

The cycle, concretely

T+00:00 FRONT sample 3 thin-evidence skills + 2 random skills for re-test T+00:10 AUCTION each candidate job bids with stake + expected information gain (EIG) T+00:20 ALLOCATE escrow split proportionally to bid; >30% reserved for random jobs T+00:30 EXECUTE sandboxed instances; ledger written OUTSIDE writespace; cost attributed live T+06:00 VERIFY independent oracle + a replication gate: 2 of 3 runs must agree T+07:00 SETTLE bank or concede stake; update hit rate, CI, authority A(s) T+07:10 DIVERGE if |observed − expected| > 2σ: open a FALSIFICATION job, halve A(s) T+07:20 COMPRESS retire duplicate skills, demote stale ones, publish evidence bundle T+24:00 RESET next cycle

The EXPECTED / OBSERVED / DIVERGED triple is the whole discipline. Current agent ledgers record what happened. SKILLA records what was predicted, what happened, and the difference — and forces a response to every difference above the noise floor. That is the object a stranger can audit.

06 The kill-switch is a theorem, not a button

Any autonomy proposal that does not include a stop condition is incomplete. Here is the one I would defend.

The hard question is not "how do we stop it." It is "how do we know it is the same agent when we check?" An agent that drifts silently is the real danger — not the agent that is overweight on a summary. So the stop condition must be a computable divergence test, not a human raising their hand:

# SKILLA divergence halter — evaluated at every cycle boundary # a "hazard" is an action in the oracle-hazard set; a "delta" is mass with no evidence but claimed success def halt(cycle): d = cycle.divergence_pct # % of claims in the last 3 cycles that failed replication h = cycle.hazard_attempts # out-of-scope or irreversible actions attempted a = cycle.authority_mass # sum of A(s) over skills the agent actually used if d > 0.15: return "HALT — replication floor breached" if h > 0: return "HALT — hazard attempted, human review required" if a < cycle.prev_authority * 0.5: return "HALT — identity drift: authority halved in one cycle" return "continue"

The third clause is the one nobody builds. It says: if the thing you were becoming is not the thing you are now, stop and prove which one you are. It catches silent drift, silent scope creep, and the failure mode where an agent learns to look busy.

This is the bridge back to your day job. A CMS enrollment transaction and an autonomous agent run both need: an immutable record, an independent verifier, a scope boundary, an acceptance criterion, and a documented stopping rule. You have been building the first four for twenty years. The fifth is the one that is new — and it is a math problem, not a policy problem.

07 What would prove this wrong

A program you cannot falsify is a manifesto. These are the tests.

Claim SKILLA makesThe test that kills itFalsified if…
Falsification pressure beats random exploration Two swarms, same models and budget, 30 cycles: one probes the frontier, one probes at random. Random arm produces equal or more verified skills per dollar.
Earned authority prevents drift Seed a failing skill at high authority. Does the system demote it within 3 cycles? A high-authority wrong skill survives 3 re-tests.
Staking suppresses self-reported success Compare claim rate in a staked vs unstaked escrow on the same task family. Claim rate is the same and replication rate does not improve.
An evidence bundle is auditable by a stranger Give a bundle to someone who has never seen the harness. Can they recompute the score? They need to ask the agent, or the authors, anything.
Skill transfer beats fresh context Measure first-try success on cycle N+1 with and without the library injected. The library contributes nothing (or hurts, via stale skills).

The most likely way this fails: the skill library becomes a landfill. Every agent writes skills, nobody retires them, and stale entries silently corrupt later decisions. That is why the retirement rule (deviation > 2σ → halve authority) and the FALSIFICATION job type must exist in cycle one, not later.

08 Build order

Each phase is a weekend or less. Each has a demo someone can see.

PHASE 0
1-2 wk

The evidence bundle

Pure engineering, zero ML. Wrap one existing agent in a manifest + hash-chained event log + oracle verdict writer. No new model logic.

DEMO ▸ hand someone a folder; they recompute the score without asking you anything.

PHASE 1
2 wk

The skill schema + a reviewer

Write skills with validity conditions and hit rates. Build the re-test sampler that re-runs 5 skills per cycle and updates CIs. This alone beats most production agent systems.

DEMO ▸ a skill's confidence interval widens visibly after a bad re-test.

PHASE 2
3 wk

Frontier + auction + escrow

Selection of thin-evidence skills. Jobs bid stakes. Escrow allocated with a reserved random sample. Financials recorded in the ledger.

DEMO ▸ the swarm abandons an over-priced job on its own and buys three cheap probes instead.

PHASE 3
2 wk

The authority formula in production

Replace static permission grants with A(s). Wire the ladder. Add the divergence halter. The halter must exist before the authority ladder is switched on.

DEMO ▸ a seeded success-claiming behavior loses authority in two cycles on its own.

PHASE 4
6 wk

The research paper

Run the falsification table's five tests. Pre-register the tests before running them. Publish results regardless of outcome.

DEMO ▸ a paper with negative results in the appendix, and a claim people can reproduce.

The total is ~14 weeks of part-time work. It is deliberately ordered so that every phase ends with something you can show — Phase 0 alone is a publishable engineering contribution, because almost nobody ships verifiable evidence bundles.

09 Honest limits

What this program does not do. Read this before you get excited.

It is not a path to AGI.

SKILLA makes autonomous systems measurably more capable at a bounded kind of work — work whose success can be verified. It says nothing about open-ended generality, and I would not claim it moves the AGI frontier at all. What it does is make the frontier legible.

It is not safe for unbounded domains.

The oracle needs a way to be wrong. Open-ended research, medicine, legal advice, and anything irreversible do not fit this harness. The authority ladder should stay below 0.5 for those domains permanently.

It is not a substitute for better models.

Every component works on top of the current generation of models and gets better as models improve. But a weak model with a perfect audit trail is still a weak model.

The economics can be gamed for a while.

A clever agent can learn to bid for cheap, safe re-tests to accumulate authority without producing new knowledge. The random-job reservation and the EIG term limit this but do not eliminate it. Expect to iterate on the incentive design; treat it as an open problem.

Why this is worth building anyway: the field's bottleneck is no longer capability. It is the inability to tell which of two capable systems deserves to win. An organisation that can answer that question — with evidence a stranger can check — has a structural advantage that better models do not erase. That is the opening, and it is built from the one thing you already have: the instinct to distrust a claim that cannot be tested.
