L12 · Initialisation & Stability: Xavier, He, and μP Intuition

The first forward pass decides whether training has a chance. Get the initial weight scale wrong by a factor of 2 and a 30-layer stack either fades to zero or saturates in the first few hundred steps — before any data can correct it. Initialisation is the one hyperparameter you set without evidence from the data.

~28 min difficulty ●●●○○ build: activation-variance-vs-depth probe
variance propagation fan-in vs fan-out Xavier gain He gain PyTorch default is not He zero-init outputs μP scaling intuition

1 · Why it exists #

A network does not start blank: it starts with random weights. What those random numbers do to the signal as it travels through L layers is a compounding multiplication. If each layer multiplies the activation scale by a factor g, then after 30 layers the scale is g30. For g = 0.9 that is 4%; for g = 1.1 it is 17×. Neither is trainable: the first dims the loss to numerical noise, the second saturates every nonlinearity and pushes the softmax into a one-hot corner where gradients are zero.

Before principled initialisation, the standard workaround was to use saturating activations (sigmoid/tanh) and keep the network shallow. Xavier/Glorot's contribution was to show that you can derive the right scale from variance bookkeeping, making deep stacks trainable. He's extension fixed it for ReLU, whose one-sided activation changes the variance budget by a factor of two. Both are one-line formulas with a two-line derivation, and both are routinely implemented wrong because library defaults are not what their name suggests.

Initialisation sets the conditioning of the optimisation problem before the first update. A wrong init cannot be fixed by more data or a better scheduler — it is why the run with "identical hyperparameters" sometimes diverges, and it is the first thing to print when a new architecture will not train.

2 · The mental model #

Analogy. Signal power is money travelling along a chain of L currency exchanges. Each exchange charges or credits a random rate. You want the expected money arriving at the far end to be the same as what you sent, and the spread (variance) to be controlled. The right exchange rule depends on how many currencies each hop touches (the fan-in) and on what fraction of the money the nonlinearity throws away.

Where the analogy breaks. Two places. (1) Backward propagation is a second chain with different exchange rates: the gradient at layer 1 depends on fan-out, not fan-in. Xavier is the compromise that balances forward and backward scale simultaneously, which is why its formula contains both fans. He's formula optimises the forward path for ReLU and accepts a backward mismatch. (2) Residual connections change the accounting entirely: with a pre-norm residual block, each layer only adds a small contribution to an existing stream, so depth does not compound an initialisation error the way it does in a plain stack. The measured consequence is the reverse of the folk belief: the residual path prevents decay but not growth (Experiment 2 below), which is why a transformer needs the norm, not just a good init.

What the formulas fix

They set the per-layer gain so that the expected squared norm of the activation is preserved from layer to layer. That makes the initial forward pass depth-independent in expectation.

What they do not fix

Correlations between rows (random rows are near-orthogonal only in high dimension), the tail of "unlucky" seeds, or downstream instability from the loss and the learning rate. A good init is necessary, not sufficient.

Why ReLU needs 2x

ReLU zeros half of its inputs, so it halves the variance of the layer's output. To keep the output variance equal to the input variance you need input variance 2x larger, i.e. He gain √2 rather than Xavier's roughly-1.

What μP adds (intuition)

Treat the width as a scaling parameter: choose which quantities must stay width-independent (activations, and updates resolved in a width-independent metric) and fix the per-layer initialisation and learning-rate multipliers to achieve that, so hyperparameters transfer across width.

3 · The mechanism #

Linear layer: y = Wx, Wij ~ N(0, σ2), x ~ iid variance v ⇒ Var(yi) = fanin · σ2 · v

Forward preservation:   fanin·σ2 = 1  ⇒  σ2 = 1/fanin
Backward preservation:   fanout·σ2 = 1  ⇒  σ2 = 1/fanout

Xavier/Glorot:   σ2 = 2/(fanin + fanout)   (compromise)
He:            σ2 = 2/fanin   (forward path with ReLU)
Offset term:   gain2 = fanin · σ2  ⇒  Var(y) = (fanin/2) · gain2 · Var(x)   for ReLU fan_in = number of input features (d_in), fan_out = d_out. The last line is the one to remember: for ReLU, a layer multiplies variance by (fan_in/2)·gain^2, because the ReLU itself halves it. Setting that product to 1 gives gain^2 = 2/fan_in, the He rule. Setting fan_in = fan_out = d gives the familiar 0.5 probability of survival and gain ≈ √(2/d).
# Variance propagation through a plain (non-residual) stack — stdlib only. import math, random random.seed(0) def forward_depth(L, d, gain, resid=False): x = [random.gauss(0, 1) for _ in range(d)] stds = [] for _ in range(L): W = [[random.gauss(0, gain / math.sqrt(d)) for _ in range(d)] for _ in range(d)] h = [max(0.0, sum(W[i][j] * x[j] for j in range(d))) for i in range(d)] x = [a + b for a, b in zip(x, h)] if resid else h mu = sum(x) / d stds.append(math.sqrt(sum((z - mu) ** 2 for z in x) / d)) return stds d = 128 for name, g in [("gain=1 (Xavier-ish)", 1.0), ("gain=sqrt2 (He)", math.sqrt(2.0))]: s = forward_depth(30, d, g) print(f" {name:22s} L1={s[0]:.3f} L2={s[1]:.3f} L5={s[4]:.3f} L30={s[-1]:.3f}") for fan_in, fan_out in [(4096, 4096), (4096, 11008), (11008, 4096)]: vx = 2.0 / (fan_in + fan_out); vh = 2.0 / fan_in print(f"fan_in={fan_in:5d} fan_out={fan_out:5d}: Xavier std={math.sqrt(vx):.5f} He std={math.sqrt(vh):.5f}")

Verified output (CPython 3.12):

gain=1 (Xavier-ish) L1=0.594 L2=0.421 L5=0.162 L30=0.000 gain=sqrt2 (He) L1=0.715 L2=0.813 L5=0.630 L30=0.483 fan_in= 4096 fan_out= 4096: Xavier std=0.01562 He std=0.02210 fan_in= 4096 fan_out=11008: Xavier std=0.01151 He std=0.02210 fan_in=11008 fan_out= 4096: Xavier std=0.01151 He std=0.01348

Read the two effects. First, gain = 1 collapses: the std falls from 0.594 at layer 1 to 0.000 by layer 30 — the signal is gone, and with it the gradient. Second, gain = √2 is stable: 0.715, 0.813, 0.630, 0.483 across 30 layers. It is not perfectly flat, because a single sample of a random matrix has finite-width noise and the "half the units are killed" approximation is not exact per layer; but the decay is slow and bounded, which is all you need to start training.

The three-row table is the other half of the lesson: Xavier and He differ only in which fan they use. For a square matrix they differ by √2 (0.01562 vs 0.02210). For an FFN's up-projection (fan_in 4096, fan_out 11008) Xavier halves its scale, and for the down-projection it differs again. This is why "use Xavier" on a transformer is a category error: the correct answer depends on the layer you are initialising and the activation that follows it.

The two traps in real code

  • A library default is not a derivation. Many frameworks default to a uniform initialisation whose scale corresponds to a gain of 1, not √2. If you call the default constructor and then add a ReLU FFN, you have silently built the collapse case. Always pass the init explicitly for every weight matrix in a new block.
  • Zero-initialising the wrong thing. Initialising the output projection of a residual branch to zero makes each block start as the identity, which is a real and widely used trick; initialising everything to zero makes every neuron in a layer identical and no symmetry is ever broken, so the model trains to a constant. Zero is a scalpel, not a paintbrush.

4 · Your hands #

Experiment 1 — Measure the gain your layer actually has

The theory predicts Var(out) = (fan_in/2)·gain2·Var(in) for ReLU. Measure it for one real-width layer instead of trusting the derivation.

import math, random random.seed(0) d = 4096 for gain in [1.0, math.sqrt(2.0)]: outs = [] for _ in range(200): x = [random.gauss(0, 1) for _ in range(d)] row = [random.gauss(0, gain / math.sqrt(d)) for _ in range(d)] outs += [max(0.0, sum(w * xi for w, xi in zip(row, x))) for _ in range(200)] var = sum(z*z for z in outs) / len(outs) print(f"gain={gain:.4f}: Var(out)={var:.3f}")

Observed: Var(out) = 0.502 for gain = 1 and 1.036 for gain = √2 — exactly what the formula predicts, since the ReLU halves the variance of a unit-variance input and the He gain doubles it back. This is the single most useful diagnostic on this page: run it on any new layer type, and if the output variance is not ~1 for unit-variance input, your init is off by a factor you can quantify.

Experiment 2 — Depth sweep, and the residual rescue

Watch the collapse as a function of depth, then add a residual connection and confirm that it changes the situation qualitatively. This is why the transformer's residual stream can be forgiving where a plain MLP is not.

for resid in [False, True]: for g in [1.0, math.sqrt(2.0)]: s = forward_depth(20, d=64, gain=g, resid=resid) print(f"resid={resid!s:5s} gain={g:.3f}: std at depth 5/10/20 = {s[4]:.3f} / {s[9]:.3f} / {s[19]:.3f}")

Verified: resid=False gain=1.000: 0.183 / 0.021 / 0.001 (collapses); resid=False gain=1.414: 0.842 / 0.812 / 0.803 (stable); resid=True gain=1.000: 3.190 / 18.596 / 883.800; resid=True gain=1.414: 8.941 / 119.079 / 25455.021. Read all four lines carefully, because the residual result is the opposite of the folk belief. The residual path prevents decay but does not prevent growth: every layer adds a non-negative ReLU contribution, so with a gain tuned for a plain stack the residual stream's std grows by roughly a factor 6–7 per five layers. That is exactly the problem a pre-norm transformer solves by normalising the branch input (L05) — the norm, not the init, caps the growth. Falsifier: if the residual case also collapsed to zero, you accidentally overwrote x instead of adding to it — the same class of bug as L03's missing +=.

Experiment 3 — Reference scales and a symmetry check

Two cheap structural checks worth running on any new model class before training: are the scales what you think, and is there any symmetry left to break?

import random, math random.seed(1) def check(fan_in, fan_out, gain=1.0): W = [[random.gauss(0, gain / math.sqrt(fan_in)) for _ in range(fan_in)] for _ in range(fan_out)] row_norms = [math.sqrt(sum(w*w for w in r)) for r in W] return sum(row_norms)/len(row_norms), max(row_norms)/min(row_norms) for fi, fo in [(4096, 4096), (4096, 11008)]: m, spread = check(fi, fo) print(f"fan_in={fi} fan_out={fo}: mean row norm {m:.3f} (target 1.000), spread {spread:.3f}") z = [[0.0] * 8 for _ in range(8)] print("all-zero layer: distinct rows?", len({tuple(r) for r in z})) print("all-zero layer: gradient for row i == row j?", True, "(identical rows receive identical gradients forever)")

Observed: mean row norm is 1.000 in both cases — which is the definition of the init, since each row's norm is √(fan_in · 1/fan_in) = 1 — with a spread of 1.084 and 1.091 (finite-width noise). And the all-zero layer has exactly one distinct row, so all its rows receive identical gradients forever. Two lessons: the init controls row norms, which is exactly the quantity that matters for a dot-product score, and symmetry must be broken by randomness, never by "small but zero".

5 · Failure modes #

  • Using Xavier where He is required (or vice versa). Symptom: loss decreases but plateaus early; per-layer activation std shrinks by ~√2 per layer. Detected by the depth probe, not by the loss curve.
  • Relying on a framework default. Symptom: a new layer type trains "fine" until you change width, then diverges. The default is not the derivation for your activation; pass the init explicitly.
  • All-zero or all-equal init. Symptom: loss falls to the marginal entropy of the labels and stops; every unit in a layer has an identical gradient. Any zero-init must be limited to a single output projection of a residual branch.
  • Init in the wrong dtype. Symptom: fp16 weights at initialisation quantise to a grid where small values become zero, killing a fraction of units before training starts. Initialise in fp32 and cast.
  • Init scale not updated for a gated FFN. Symptom: SwiGLU block's output variance is half of a ReLU block's (the gate multiplies by SiLU(x) whose mean is positive-but-small), so depth-scaled models start asymmetric. Measure the block's output variance after switching activations (L11).
  • Embedding init too large or too small. Symptom: the residual stream starts 10× the scale the block expects, forcing every layer to spend capacity rescaling; or embeddings start near 0 and the first layers see near-constant input. The initial embedding std should be chosen so the residual stream's RMS is comparable to the norm layer's expected output.
  • MuP assumptions violated. Symptom: hyperparameters that were tuned at one width do not transfer to another — the classic "the recipe only works at the width we tried". Check that every layer's init and LR multiplier follows the width-scaling rule before concluding the recipe generalises.

7 · Self-check #

Q1. Derive the He rule from the variance propagation identity.

Reveal answer

For y = Wx with Wij ~ N(0,σ2) and x components iid with variance v: Var(yi) = ∑j Var(Wijxj) = fan_in·σ2·v. ReLU then multiplies the variance by ~1/2 (it zeroes half the mass, and for a zero-mean symmetric input E[max(0,z)2] = v/2). So after one layer Var = (fan_in/2)·σ2·v. Requiring that to equal v gives σ2 = 2/fan_in. Verified numerically: unit input variance, d = 4096, gain = √2 gives output variance 1.036.

Q2. For d = 4096, what std does He prescribe, and what std does Xavier prescribe if fan_out = 11008?

Reveal answer

He: σ = √(2/4096) = √0.000488 ≈ 0.02210 (verified). Xavier with fan_in = 4096, fan_out = 11008: σ = √(2/15104) = √0.0001324 ≈ 0.01151 (verified). So on the up-projection of a SwiGLU FFN, Xavier gives a std roughly half of He — a factor of 4 in variance, which is exactly the kind of discrepancy that turns into a collapse over 30 layers.

Q3. Diagnostic: a new 24-layer model's loss starts at the value you expect and then flatlines while all layers show near-zero gradient norm. What do you check first?

Reveal answer

Initialisation scale. Run the variance probe: if the per-layer activation std decays with depth, the init is too small (gain < √2 with ReLU, or a default init). Confirm the gradient: a forward signal that decays by 0.5 per layer is squared in the backward pass, so gradients vanish long before the loss looks obviously broken. Second check: whether the output projection is zero-initialised where it should not be, or whether embeddings are so small that the first layer sees a near-constant input.

Q4. Why does a residual connection change the depth-scaling problem, and what does that imply about init for transformers?

Reveal answer

In a plain stack, every layer's scale multiplies the running total, so an error compounds exponentially in depth. With a residual, the output is the sum of the identity path and a branch: the identity carries the input forward unchanged no matter what the branch's scale is, so the signal cannot decay to zero unless the branch actively cancels it. Consequently a transformer's init mainly controls the branch contribution and does not need per-depth rescaling to keep activations alive; it still matters for the branch's own variance and for the growth of the residual stream's norm (L05).

Q5. What is the one-line intuition for μP, and what observable would tell you a recipe has failed to be width-transferable?

Reveal answer

μP fixes a width-independent parameterisation (per-layer init scale and per-layer LR multiplier) so that the same tuned hyperparameters work at every width. Observable: tune at width W, retrain at 4W, and if the optimal LR or the loss curve shifts materially, the recipe is not width-transferable (a "non-μP" parameterisation). The check is cheap: two widths, one LR sweep each, compare the argmin. Note that many published recipes are simply not μP; the assumption must be tested, not assumed.
