L05 · Normalization: LayerNorm, RMSNorm, and the Residual Stream

Stack 24 layers without normalisation and each layer either shrinks its input toward zero or blows it up, depending on its weight scale — so the learning rate that works for layer 1 is wrong for layer 24. Normalisation pins the scale of the signal at every point in the network. It is the cheapest stability mechanism in deep learning and the most commonly mis-engineered.

1 · Why it exists #

Consider what a deep stack does to scale. Each layer computes h = Wx; if W has entries of variance σ2 and x has unit variance in d dimensions, then each output has variance dσ2. If dσ2 is 0.9, then after 30 layers the signal is 0.930 ≈ 4% of its original size; if it is 1.1, it is 1.130 ≈ 17×. The network's behaviour is a 30th power of a number you cannot control, because the weights move during training. The gradient is subject to the same compounding, in the opposite direction, which is why deep pre-normalisation-era networks needed long warmup and were hard to train past a few layers.

BatchNorm solved this in vision by normalising across the batch, but its statistics depend on the batch — catastrophic for sequence models where batch composition varies and dangerous at inference where you must use frozen running statistics. LayerNorm (Trans­former, 2017) normalises across the feature axis of each token independently: no batch statistic, no train/eval mismatch, well-defined for a batch of one.

Normalisation is a preconditioner, not a regulariser. It makes the optimisation problem well-conditioned so one learning rate works for all layers. Removing it does not make the model "more expressive" — it makes the loss landscape too curved to walk with a fixed step size.

2 · The mental model #

Analogy. Every signal path in a factory is re-metered at each station: whatever came in, it leaves at exactly 1.0 volts. The gain knob (the learnable γ) lets each station choose a different voltage deliberately, so information about magnitude is not lost — it is re-learned expressively rather than accidentally.

Where the analogy breaks. A voltage regulator has a measurable distortion cost; LayerNorm has an information cost that is exact: it removes two directions from every token vector. Subtracting the mean kills the "all features equal" direction; dividing by the std kills the "overall magnitude" direction. The layer can re-introduce both through β and γ, but only at a per-token cost that a following linear layer might need. RMSNorm removes only one direction (magnitude) because it never subtracts the mean — that is the entire difference, and it is why RMSNorm can be cheaper and as good or better in transformers.

What LayerNorm does

Per token: subtract the feature mean, divide by the feature std, then scale by γ and shift by β. Output has zero mean, unit variance per token, before γ.

What RMSNorm does

Per token: divide by RMS = √(mean(x2) + ε), then scale by γ. No mean subtraction, no β. Cheaper by one reduction and one elementwise pass.

What "pre-norm" means

Normalise the input to each sublayer: x = x + f(norm(x)). The residual path is a clean unnormalised highway from input to output. This is what makes deep stacks trainable without warmup tricks.

Why the residual stream grows

Each block adds to x, so ‖x‖ grows roughly as √depth with random additions. With pre-norm, the final norm absorbs this; without a final norm, logits grow with depth.

3 · The mechanism #

LayerNorm:   μ = (1/d)∑xi,   σ2 = (1/d)∑(xi − μ)2,   x̂i = (xi − μ)/√(σ2 + ε),   yi = γix̂i + βi

RMSNorm:   r = √( (1/d)∑xi2 + ε ),   yi = γi xi/r Pre-norm block: x' = x + Attn(LN(x)), then x'' = x' + MLP(LN(x')). Post-norm block: x'' = LN(x + Attn(x)) and then LN again around the MLP. Note: LN and RMSNorm reduce over the FEATURE axis (each token independently), never over the batch or sequence — that is what makes them usable at inference on a single token.

The backward pass, closed form

This is the derivation that appears in every implementation and is copied wrong about as often. Let gi = dyiγi be the incoming adjoint through the scale, and hi = x̂i.

dxi = (1/(d·σ)) [ d·gi − ∑jgj − hi ∑jgjhj ]
dγi = dyihi,   dβi = dyi with σ = √(σ2+ε). Three terms: propagate the gradient, remove the component along the constant direction, remove the component along h itself. Sanity check: ∑i dxi = 0 exactly, because LN output cannot change if you add a constant to all inputs.
dxi = (1/r)[ gi − (xi/r2)·(1/d)∑jgjxj ]   where gi = dyiγi
dγi = dyixi/r One projection instead of two. RMSNorm's gradient is not mean-free, because RMSNorm output is not invariant to adding a constant to the inputs — only to a global positive rescaling, which is the property that actually matters for optimisation condition.
# LayerNorm and RMSNorm: forward + closed-form backward, verified against finite differences. import math def ln_fwd(x, g, b, eps=1e-5): n = len(x); mu = sum(x) / n; var = sum((xi - mu) ** 2 for xi in x) / n inv = 1 / math.sqrt(var + eps); xh = [(xi - mu) * inv for xi in x] return [xh[i] * g[i] + b[i] for i in range(n)] def ln_bwd(x, g, dy, eps=1e-5): n = len(x); mu = sum(x) / n; var = sum((xi - mu) ** 2 for xi in x) / n inv = 1 / math.sqrt(var + eps); xh = [(xi - mu) * inv for xi in x] dxh = [dy[i] * g[i] for i in range(n)] dx = [inv / n * (n * dxh[i] - sum(dxh) - xh[i] * sum(dxh[j] * xh[j] for j in range(n))) for i in range(n)] return dx, [dy[i] * xh[i] for i in range(n)] x = [0.4, -1.2, 0.9, 2.1, -0.3]; g = [1.0]*5; b = [0.0]*5 dy = [0.5, -0.2, 1.0, 0.0, 0.7] dx, dg = ln_bwd(x, g, dy) fd = [] for i in range(5): xp, xm = list(x), list(x); xp[i] += 1e-6; xm[i] -= 1e-6 fd.append((sum(v*w for v, w in zip(ln_fwd(xp, g, b), dy)) - sum(v*w for v, w in zip(ln_fwd(xm, g, b), dy))) / 2e-6) print("LN dx analytic:", [round(v, 6) for v in dx]) print("LN dx finite :", [round(v, 6) for v in fd]) print("sum dx = ", sum(dx), " <- must be ~0")

Verified output (CPython 3.12):

LN dx analytic: [0.088814, -0.454415, 0.511387, -0.452002, 0.306216] LN dx finite : [0.088814, -0.454415, 0.511387, -0.452002, 0.306216] sum dx = 2.7755575615628914e-17 <- must be ~0

The finite differences agree to all six printed decimals and the sum is zero to float64 precision. That is the proof that the three-term formula is right; if you omit the middle term (−∑gj) it fails, and the failure is invisible in training except as a slightly worse loss curve. This is why L03's oracle test belongs in CI.

Why pre-norm, and what the residual stream costs

In pre-norm, every sublayer's output is added to an unnormalised running sum. After L blocks, the residual stream is the sum of the token embedding plus L contributions. Two consequences:

  • The identity path is clean. Gradient flows from the loss to the embedding through the additions with no normalisation derivative in the way, so vanishing gradients are not the limiting factor for depth. That is why pre-norm made 100+ layer transformers routine.
  • Magnitude grows with depth. If each added contribution has RMS ~c, the stream's RMS grows roughly as c√L (uncorrelated sums add in quadrature). Pre-norm therefore needs a final norm before the output head; post-norm bakes normalisation into every block and needs no final norm but has a much harder optimisation problem, with the residual path passing through the normaliser each time.

One more property worth knowing because it is used everywhere later: because LN's output has fixed variance regardless of input scale, the composition LN(γ·x) is invariant to the overall scale of x. So a weight matrix feeding into a norm can be rescaled arbitrarily without changing the function — which is exactly the degree of freedom that weight decay and μP-style parameterisation exploit (L12, L43).

4 · Your hands #

Experiment 1 — Watch activation scale die with depth, and watch norm stop it

This is the failure that forced normalisation into existence, reproduced in 30 lines with no framework.

import math, random random.seed(0) def layer_stats(norm, depth, d=64): x = [random.gauss(0, 1) for _ in range(d)] for _ in range(depth): W = [[random.gauss(0, 1 / math.sqrt(d)) for _ in range(d)] for _ in range(d)] h = [max(0.0, sum(W[i][j] * x[j] for j in range(d))) for i in range(d)] if norm == "layernorm": mu = sum(h)/d; var = sum((z-mu)**2 for z in h)/d h = [(z-mu)/math.sqrt(var + 1e-5) for z in h] elif norm == "rmsnorm": rms = math.sqrt(sum(z*z for z in h)/d) h = [z/(rms + 1e-6) for z in h] x = h return round(sum(x)/d, 5), round(math.sqrt(sum(z*z for z in x)/d), 5) for mode in ["none", "layernorm", "rmsnorm"]: print(mode, "(mean, rms) at depth 12:", layer_stats(mode, 12)) for mode in ["none", "rmsnorm"]: print(mode, "rms by depth 1..10:", [layer_stats(mode, D)[1] for D in range(1, 11)])

Verified: no norm gives (0.00756, 0.01401) at depth 12 — the signal is 70× smaller than it started — while LayerNorm gives (-0.0, 0.99999) and RMSNorm gives (0.60002, 1.0). Across depth the unnormalised RMS reads [0.7622, 0.4479, 0.3447, 0.3311, 0.1944, 0.124, 0.1072, 0.0409, 0.0438, 0.0218] while RMSNorm reads [1.0] ten times. Note RMSNorm's mean is not zero (0.6) — that is the visible difference from LayerNorm, and it is harmless because the following linear layer can learn it.

Experiment 2 — Prove the scale-invariance claim

The degree of freedom that weight decay exploits. Take any vector, scale it by 1000, normalise, compare.

python -c "x=[0.4,-1.2,0.9,2.1]; n=lambda v:[(a-sum(v)/len(v)) for a in v]; import math; z=n(x); print('LN(x) ', [round(a/math.sqrt(sum(b*b for b in z)/4+1e-5),6) for a in z]); z2=n([1000*a for a in x]); print('LN(1000x)', [round(a/math.sqrt(sum(b*b for b in z2)/4+1e-5),6) for a in z2])"

Observed: LN(x) [-0.12666, -1.477696, 0.295539, 1.308816] and LN(1000x) [-0.12666, -1.477701, 0.29554, 1.308821] — equal to five decimals, differing only in the sixth because ε = 1e-5 sits inside the sqrt and the bigger variance dilutes it. Normalising erases the input scale (up to ε), so multiplying a weight matrix by c and its successor by 1/c changes the function not at all. Consequence: (a) weight decay on a matrix feeding a norm is not shrinking the function — it walks along a zero-effect direction, which is why its interaction with training dynamics is subtle, and (b) any attempt to control "activation magnitude" by penalising weights before a norm has no effect on activations. This is also why ε is not free: it makes the layer slightly scale-dependent, and in fp16 an ε that is too large relative to the variance visibly changes behaviour.

Experiment 3 — Price the normaliser

RMSNorm is cheap; the question is whether the difference matters at your scale. Count elements touched per token and per layer for a 4096-wide model.

d, L, T = 4096, 32, 8192 def touches(kind): per_token = {"layernorm": d + d, "rmsnorm": d + d, "layernorm+beta": d + d + d}[kind] return per_token * T * L * 2 # 2 norms per block for kind in ["rmsnorm", "layernorm", "layernorm+beta"]: print(kind, "->", touches(kind) / 1e9, "G element-touches for the whole forward pass") print("matmul FLOPs per token ~ 2*N_params; at 7e9 params and 8192 tokens:", round(2*7e9*8192/1e12, 2), "TFLOP")

Observed: 4.3 G, 4.3 G and 6.4 G element-touches respectively — pennies next to the ~115 TFLOP of matmuls. So the reason RMSNorm dominates modern architectures is not raw FLOPs; it is (a) fewer memory reads at inference where you are bandwidth-bound (L09) and (b) a slightly simpler gradient path, which matters in low precision. Do not justify an architecture choice with a FLOP count that is 0.004% of the total — that is a red flag in a design review.

5 · Failure modes #

  • Normalising over the wrong axis. Symptom: everything runs, loss is stuck near ln(V); the model behaves like a bag of words. When tokens are in a batch and you reduce over the sequence dimension, you mix documents together. Assert shapes: LN over the last dimension only.
  • eps in the wrong place. Symptom: training fine, inference with a batch of one produces different logits — or NaN on all-zero rows. ε must be added before the sqrt, inside the variance: √(σ2 + ε), not √σ2 + ε.
  • Missing final norm with pre-norm. Symptom: logits (and therefore initial loss) grow with depth; a deep model with the same LR behaves worse than a shallow one. Pre-norm needs a final LayerNorm/RMSNorm before the output head.
  • Norm statistics computed in low precision. Symptom: loss spikes correlated with sequences containing large activations; happens when the variance sum is accumulated in fp16 and overflows. Accumulate the reduction in fp32.
  • Post-norm with a high LR and no warmup. Symptom: divergence in the first few hundred steps, recovering only with warmup. That is the historical reason warmup and post-norm were coupled; pre-norm removes most of this sensitivity.
  • 1-D norm parameters included in weight decay. Symptom: gain parameters drift toward zero over long runs, suppressing whole feature directions. Symptom is subtle: slightly worse loss, worse long-context behaviour. Exclude 1-D params from decay (L04).

7 · Self-check #

Q1. Why is LayerNorm preferred over BatchNorm for sequence models?

Reveal answer

BN normalises each feature across the batch, so its statistics depend on batch composition and on which other sequences are in the batch; at inference you must freeze running statistics, creating a train/eval mismatch. Sequence lengths vary, so per-feature statistics over a batch of padded sequences are biased. LN normalises each token independently over its own features: no batch dependence, identical behaviour at train and inference, well defined for a single token — the exact requirement for autoregressive decoding.

Q2. How many directions of variation does LN remove per token, and how many does RMSNorm remove? What information is lost in each case?

Reveal answer

LN removes two: the mean direction (1,1,…,1) and the radial direction (magnitude). RMSNorm removes only the radial direction. Lost information under LN: overall offset and overall scale, both recoverable only via β and γ. Under RMSNorm: overall scale only. Neither loses relative information between coordinates, and both are invariant enough that a following linear layer can undo either — but RMSNorm leaves the mean channel intact for free, which is part of why it works well with no β.

Q3. Quantitative: a 12-layer stack, no norm, per-layer variance multiplier 0.98. What fraction of the input RMS survives to layer 12? What if it is 1.02?

Reveal answer

RMS scales as the square root of the variance multiplier to the power L: √(0.9812) = 0.986 ≈ 0.886 (11% loss). For 1.02: 1.026 ≈ 1.126 (13% growth). At 32 layers the same 2% error becomes 0.9816 ≈ 0.72 and 1.0216 ≈ 1.37 — exponential in depth, hence unmanageable without normalisation.

Q4. Diagnostic: your model's initial loss is close to ln(V) and improves, but a 48-layer version trains visibly worse than a 24-layer one at the same LR. What do you check first?

Reveal answer

Whether the final norm before the output head is present (pre-norm without a final norm grows logits with depth), then the per-layer activation RMS profile to look for a decline or blow-up, then whether warmup is long enough for the depth. Also check the residual add's scaling (some implementations use 1/√2 on both branches) and that eps is inside the sqrt. A depth-dependent degradation with a fixed LR is almost always a residual-scale issue.

Q5. The backward rule for LN includes a term −hi∑jgjhj. Which test would catch a missing term, and why would training merely look "slightly worse" rather than crash?

Reveal answer

The finite-difference oracle from L03/Experiment here: compare analytic dx against central differences on random inputs and assert relative error < 1e-5. Omitting the h-projection term leaves a gradient that still points generally downhill (it is a projection of the true gradient onto a subspace), so the loss still decreases — just with a biased direction and typically a worse final loss and worse stability. That is exactly why silently-wrong gradients survive for weeks without a crash signal and why the oracle test is mandatory.
