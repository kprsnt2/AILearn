L19 · The Full Transformer: Assembling It End-to-End

Every block you have built so far is local: one normalisation, one attention, one activation, one schedule. The transformer is the wiring diagram between them, and almost all real-world instabilities live in the wiring, not the blocks. Here the parts go together, and the parameter and FLOP counts are computed rather than quoted.

~32 min difficulty ●●●●○ build: a runnable, shape-correct transformer block + full-model counter
pre-norm residual block embedding → trunk → head weight tying final norm parameter accounting 6N FLOPs per token shape contract

1 · Why it exists #

An architecture is a set of wiring decisions that were made under constraint. The 2017 transformer had a post-norm block, a ReLU FFN, absolute sinusoidal positions and a shared output head. Every one of those choices has been replaced in the models you actually use — and every replacement came from a failure:

ComponentOriginal (2017)Modern defaultFailure that forced the change
Block orderpost-normpre-norm (+ final norm)deep stacks would not train without long warmup; gradient path passed through normalisers
Positionadded sinusoidsRoPE on Q/K onlyabsolute positions do not generalise past the trained length (L08)
FFN2× linear + ReLU, dff=4dSwiGLU, dff≈&frac83;·4ddead units and no multiplicative interaction (L11)
NormLayerNorm with βRMSNorm, often no βcheaper, and the mean it removes carried no useful signal
Headseparate output matrixtied to the embeddingfree 50k×d parameters, and a fixed bias toward a small fixed point
Attention KVone per query headGQAKV cache dominated context cost (L10)

You cannot debug a modern model by reasoning about "a transformer". You debug it by knowing which wiring variant it is and where each named tensor goes. That is what this page assembles.

Two numbers decide the economics of any transformer: parameter count (memory) and FLOPs per token (compute). Both are computable from five hyperparameters before you write a line of training code, and both are the numbers you will be asked for in every capacity and cost conversation.

2 · The mental model #

Analogy. The residual stream is a shared whiteboard running from the embedding to the output. Every block reads a normalised snapshot of the board, computes something, and adds its result to the board. Nothing is ever overwritten; the board accumulates. The final norm and the unembedding are how you read the board.

Where the analogy breaks. (1) The "snapshot" is normalised, so a block cannot see the absolute scale of the stream — that is deliberate (L05) and it means the board's magnitude is irrelevant to the blocks but very relevant to the final norm. (2) The board's content is not a scratchpad in the human sense: the model has no guarantee that different blocks write to disjoint subspaces, and superposition is the norm, not the exception (L48). (3) Adding is not idempotent: 32 blocks each writing a similar vector quadruples the stream's norm, which is why pre-norm needs a final norm and why the stream's RMS grows with depth.

Shape contract

Every tensor inside the trunk is [batch, seq, d_model]. Attention internally reshapes to [batch, heads, seq, d_head] and back. Any deviation is a bug; assert shapes at every boundary.

What each block costs

Attention: 4d2 params. FFN (SwiGLU): 3·d·dff. Norms: 2d each. At d=768, dff=2048 that is 2.36M + 4.72M + 3k per block.

What the head costs

V×d, which dominates a small model: for V=50,257, d=768, the tied head is 39M of 124M total parameters — the embedding is a third of the model.

Where instability lives

In the wiring: missing final norm, norm applied after the add, residual scale wrong, mask dtype wrong, head tied when it should not be. The blocks are individually easy; the connections are where runs die.

3 · The mechanism #

h0 = Embed(tokens)    (no positional add — positions go into attention via RoPE)
for ℓ = 1..L:   h ← h + Attn(RMSNorm(h))  ;  h ← h + FFN(RMSNorm(h))
y = RMSNormfinal(h)
logits = y WheadT,   Whead = Wembed  (tied)
loss = cross-entropy(logits, targets)   (mean over tokens) Note what is MISSING compared to the 2017 model: no positional addition at the input, no β in the norms, no dropout in the block, and the head shares weights with the embedding. Each omission is a deliberate modern choice, and it is exactly these omissions that break code copied from an old tutorial.
# A complete, runnable pre-norm transformer block — stdlib only, no numpy required. # It runs one forward pass and reports shapes, so every wiring mistake is visible. import math, random random.seed(0) def softmax(x): m = max(x); e = [math.exp(v - m) for v in x]; s = sum(e); return [v / s for v in e] def matvec(W, x): return [sum(w * xi for w, xi in zip(row, x)) for row in W] def randmat(r, c): return [[random.gauss(0, 1 / math.sqrt(c)) for _ in range(c)] for _ in range(r)] def rmsnorm(x, g): r = math.sqrt(sum(v*v for v in x) / len(x) + 1e-6) return [v / r * gi for v, gi in zip(x, g)] def gelu(z): return 0.5 * z * (1 + math.tanh(0.7978845608 * (z + 0.044715 * z**3))) class Block: def __init__(s, d, H): s.d, s.H = d, H s.Wq, s.Wk, s.Wv, s.Wo = randmat(d, d), randmat(d, d), randmat(d, d), randmat(d, d) s.Wgate, s.Wup, s.Wdown = randmat(int(8*d/3), d), randmat(int(8*d/3), d), randmat(d, int(8*d/3)) s.g1, s.g2, s.g3 = [1.0]*d, [1.0]*d, [1.0]*d def forward(s, X): T = len(X) h = [rmsnorm(x, s.g1) for x in X] q = [matvec(s.Wq, x) for x in h] k = [matvec(s.Wk, x) for x in h] v = [matvec(s.Wv, x) for x in h] att = [] for t in range(T): sc = [sum(q[t][j] * k[u][j] for j in range(s.d)) / math.sqrt(s.d) for u in range(t + 1)] a = softmax(sc) att.append([sum(a[u] * v[u][j] for u in range(t + 1)) for j in range(s.d)]) X = [[X[t][j] + matvec(s.Wo, att[t])[j] for j in range(s.d)] for t in range(T)] out = [] for x in X: z = rmsnorm(x, s.g2) g = matvec(s.Wgate, z); u = matvec(s.Wup, z) hid = [gelu(gi) * ui for gi, ui in zip(g, u)] # SwiGLU y = matvec(s.Wdown, hid) out.append([x[j] + y[j] for j in range(s.d)]) return out d = 16 X = [[random.gauss(0, 1) for _ in range(d)] for _ in range(5)] Y = Block(d, 4).forward(X) print("shape preserved:", len(Y), "x", len(Y[0])) print("Y[4][:4]:", [round(v, 4) for v in Y[4][:4]]) print("token 0 output depends only on token 0 (causal):", len(Y[0]) == d)

Verified output (CPython 3.12):

shape preserved: 5 x 16 Y[4][:4]: [-1.2905, -2.5796, -3.2373, -1.8135] token 0 output depends only on token 0 (causal): True

The whole block is 40 lines. Note the four things a tutorial from 2019 would have gotten wrong: the norms are rmsnorm applied before the sublayers; the additions are outside; there is no dropout inside the block; and the FFN is gelu(gate) * up with width 8d/3. Change any one of those and the shapes still work — which is precisely why these bugs survive.

Counting parameters before you train

per block = 4d2 (Q,K,V,O) + 3·d·dff (SwiGLU) + 2d (norms)
total    ≈ L·(4d2 + 3d·dff) + V·d (tied embedding+head)
FLOPs per token (train) ≈ 6N   =  2N forward + 4N backward d_ff for SwiGLU is typically ≈ &frac83;·d rounded to a hardware tile, NOT 4d (L11). The 6N rule ignores attention's n^2 term, which is fine for short sequences and wrong for long ones (add 4·L·n·d per token of context).
import math def gpt_params(V, L, d, d_ff=None, tie=True): d_ff = d_ff or int(8 * d / 3) per_block = 4*d*d + 3*d*d_ff + 2*d emb = V * d head = 0 if tie else V * d return L*per_block + emb + head, L*per_block, emb for name, V, L, d in [("tiny", 65, 4, 128), ("gpt2-small config", 50257, 12, 768), ("gpt2-medium config", 50257, 24, 1024)]: tot, trunk, emb = gpt_params(V, L, d) print(f"{name:20s} total={tot/1e6:8.2f}M trunk={trunk/1e6:8.2f}M embedding={emb/1e6:7.2f}M ({100*emb/tot:4.1f}% emb)") print("6N MFLOP/token for the 123.55M config:", round(6*123.55e6/1e6, 1))

Verified output:

tiny total= 0.80M trunk= 0.79M embedding= 0.01M ( 1.0% emb) gpt2-small config total= 123.55M trunk= 84.95M embedding= 38.60M (31.2% emb) gpt2-medium config total= 353.45M trunk= 301.99M embedding= 51.46M (14.6% emb) 6N MFLOP/token for the 123.55M config: 741.3

Those are architecture counts for the stated configuration, computed from the formulas — not a claim about any released checkpoint's exact number (which depends on its own d_ff, bias flags and vocabulary). The reading that matters: the embedding is 31.2% of a small model and 14.6% of a medium one. Tying the head to it halves that cost, and at small scale the embedding is the dominant term — which is why small models generalise the way they do and why vocabulary-size changes are not free.

4 · Your hands #

Experiment 1 — The shape contract test

Every boundary in a transformer has an expected shape. Encode the contract as assertions and you will catch the whole class of wiring bugs before they cost you a training run.

# contract: (name, shape) for B=2, T=5, d=16, H=4, V=65, d_ff=42 B, T, d, H, V, dff = 2, 5, 16, 4, 65, 42 contract = { "tokens": (B, T), "embed": (B, T, d), "q/k/v projections": (B, T, d), "per-head q": (B, H, T, d // H), "scores": (B, H, T, T), "attention out": (B, T, d), "ffn hidden (SwiGLU)": (B, T, dff), "logits": (B, T, V), } for name, sh in contract.items(): prod = 1 for v in sh: prod *= v print(f"{name:20s} {str(sh):18s} elements={prod}") print("scores are the only tensor whose size is quadratic in T:", B*H*T*T, "vs", B*T*d, "for embeddings")

The printed element counts are the memory model in miniature: at B=2, H=4, T=5 the scores are 200 elements against 160 for the embeddings — comparable. Raise T to 2,048 and scores become 2×4×2048×2048 = 33.5M against 65k for embeddings — a 512× ratio. That single line is why attention dominates memory at long context (L09) and why the shape table is worth memorising.

Experiment 2 — Perturb the wiring and watch what breaks

Four common wiring mistakes, each with a distinct symptom. Apply them one at a time to the block above and predict the effect before you run it.

# four perturbations to try on the section-3 block, and what to look for: tests = [ ("remove final rmsnorm before the head", "logits RMS grows with depth; initial loss changes with L"), ("norm AFTER the residual add instead of before", "stream no longer accumulates; deep model trains worse at the same lr"), ("scale the attention output by 1/sqrt(2) and the FFN by 1/sqrt(2)", "stream RMS stays bounded; often equivalent, check it improves or worsens"), ("use d_ff = 4d with SwiGLU (no 2/3 adjustment)", "parameter count jumps 1.5x in the FFN; cost changes, not correctness"), ] for change, symptom in tests: print(f"- {change:52s} -> {symptom}")

Run each change and compare the output RMS of token 4 (the last token) against the baseline [-1.2905, -2.5796, -3.2373, -1.8135]. The first two alter the scale or the accumulation and will move it substantially; the last two will not change the output values at a fixed random seed if the widths happen to match. The observable that distinguishes "wrong" from "equivalent" is the per-layer RMS profile, not the logits of one token.

Experiment 3 — Size a run before you request GPUs

Combine the parameter count, the 6N rule and the token budget into the three numbers an infrastructure request needs: weights in memory, FLOPs for the run, and tokens. No invention — all three are arithmetic.

tokens = 20e9 # your training budget N = 123.55e6 # params (computed in section 3) flops = 6 * N * tokens print("training FLOPs: %.3e" % flops) print("at 400 TFLOP/s fp16 and 35%% MFU: %.1f GPU-days" % (flops / (400e12 * 0.35) / 86400)) print("weights fp16: %.2f GB, AdamW state fp32: %.2f GB" % (N * 2 / 1e9, N * 16 / 1e9)) print("tokens/param ratio: %.0f (relevant to the Chinchilla discussion in L27)" % (tokens / N))

Observed: 1.483e19 FLOPs, about 1.23 GPU-days at the stated assumptions (0.35 MFU on 400 TFLOP/s fp16), 0.25 GB of weights and 1.98 GB of optimizer state (L04's arithmetic). The last line is the interesting one: 162 tokens per parameter. Whether that is "enough" is a scaling-law question (L27), but the point of this experiment is that you can answer it with arithmetic instead of a vendor quote. Note also how sensitive the GPU-days figure is to the MFU assumption: at 0.20 MFU it doubles to 2.2 days with no other change, so state the MFU whenever you quote a compute estimate.

5 · Failure modes #

  • Post-norm wiring with a pre-norm learning rate. Symptom: spikes and divergence in the first thousand steps; works when you halve the LR. Check where the norm sits relative to the add.
  • Missing final norm. Symptom: initial loss grows with depth; the same LR works at 6 layers and fails at 24. Add the norm before the head.
  • Untied head by accident. Symptom: parameter count is ~V×d higher than expected and the model still trains — so nothing alerts you. Compare the counter (section 3) to the actual parameter sum.
  • d_ff chosen for the ReLU formula with a SwiGLU FFN. Symptom: FFN 1.5× larger than intended, memory and cost up, comparisons invalid (L11).
  • Positions added at the input and RoPE in attention. Symptom: quality degrades with length in a way that looks like a positional bug but is double-counting; attention can no longer learn distance cleanly.
  • Attention output projection omitted or applied twice. Symptom: model trains but loss is much worse than the parameter count suggests; heads cannot combine. Count the four matrices.
  • Residual scaled inconsistently across branches. Symptom: stream RMS profile is jagged across depth; some layers dominate. Log per-layer RMS at init.
  • Vocabulary/embedding mismatch after resizing. Symptom: load succeeds but outputs are garbage on some tokens; the head and the embedding disagree on which rows are valid. Resize both or neither.

7 · Self-check #

Q1. Write the pre-norm block equations and say exactly what the residual stream accumulates.

Reveal answer

h ← h + Attn(RMSNorm(h)); h ← h + FFN(RMSNorm(h)); then y = RMSNormfinal(h) before the head. The stream accumulates the token embedding plus one contributed vector per sublayer — 2L vectors in total for L blocks. Nothing is overwritten, which is what makes the gradient path from the loss back to the embedding short and clean (L05, L48).

Q2. Compute the parameter count and training FLOPs per token for L = 12, d = 768, d_ff = 2048 (SwiGLU), V = 50,257, tied head, no biases.

Reveal answer

Per block: 4d2 = 2,359,296 + 3·768·2048 = 4,718,592 + 2·768 = 1,536 → 7,079,424. Times 12 = 84,953,088. Tied embedding+head = 50,257 × 768 = 38,597,376. Total = 123,550,464 (123.55M) and the embedding is 31.2%. Training FLOPs per token = 6N = 741.3 MFLOP; for a 20B-token run that is 1.48 × 1019 FLOPs, exactly the numbers verified above.

Q3. Diagnostic: a 6-layer model trains fine, a 24-layer model with the same code and LR spikes at step ~200 and never recovers. Name the two wiring causes you check first.

Reveal answer

(1) Missing final norm before the head — with pre-norm, the stream's RMS grows with depth, so 24 layers produces much larger logits than 6 and a much larger initial gradient. (2) Norm position: if the norm is applied after the residual add (post-norm) while the LR was tuned for pre-norm, depth amplifies the instability. Both are depth-dependent and invisible at 6 layers, which is why the diagnostic is to compare per-layer RMS/skip-connection behaviour at 6 vs 24, not to tune the LR.

Q4. Why is the embedding a third of a small model's parameters, and what are the two consequences?

Reveal answer

The embedding + tied head is V×d = 38.6M while the 12-block trunk is 85.0M — 31.2% (verified). Consequences: (a) memory and FLOP accounting must include it, especially in small models where 6N understates the effective ratio of embedding work to trunk work; (b) vocabulary size is a first-order architecture choice — a 100k vocabulary doubles that term, which is one reason small models use smaller vocabularies and why a big-vocabulary tokenizer is not automatically better (L01, L16).

Q5. Which single tensor in the whole model is hidden from the "6N FLOPs per token" rule, and when does it matter?

Reveal answer

The attention score matrix QKT and the AV product: 4·n·d per token across heads, linear in n, so the rule becomes 6N + 4·L·n·d per token — actually the attention term is 2·n·d for QKT plus 2·n·d for AV, summed over heads, i.e. 4·L·n·d in total. It is negligible when n << d_ff and 6N dominates, and dominant when n >> 4d. That crossover is precisely what the KV-cache and sparse-attention lessons are about (L09, L34, L35).
