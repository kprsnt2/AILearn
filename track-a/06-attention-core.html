L06 · Self-Attention From First Principles

Attention is a soft, learned lookup: each token asks a question, every earlier token advertises a key, and the answer is a weighted average of values. Get the scaling, the mask, and the softmax stability right and you have the block that every modern LLM is made of — and the exact source of their quadratic memory bill.

~35 min difficulty ●●●○○ build: numpy attention with correct masking + memory model
query / key / value scaled dot product sqrt(d_k) variance argument causal mask -inf masking softmax max-subtraction O(n^2) score matrix attention dropout

1 · Why it exists #

Before attention, sequence models carried information through a fixed-size state: an RNN compresses everything seen so far into one vector, a CNN only sees a fixed-width window. Both fail in the same way, and it is an audit problem more than a modelling problem: the model cannot point at the evidence it used. A compliance question that depends on clause 4 of page 2 and a date on page 9 has two long-range dependencies; an RNN must have squeezed both into a single hidden state, and past a few dozen tokens the early ones are numerically decayed. Attention replaces "carry a summary" with "look back at everything, weighted".

The mechanism is also the reason modern LLMs can be audited at all: the attention weights are an explicit, inspectable matrix saying which tokens influenced which output positions. Whether those weights are a faithful explanation is a separate question (see L49), but the structure gives you a hook that a hidden state never does.

Attention = learned, content-based, differentiable lookup. Cost = O(n2) scores and O(n2) memory per head, per layer. Every trick in Track B — KV cache, GQA, MLA, sparse attention, FlashAttention — is a negotiation with that one quadratic, so you need to be able to compute it exactly.

2 · The mental model #

Analogy. A library. Each token writes a query ("I need the date this policy took effect"). Every token also posts a key ("I am a date") and files a value (its content). Attention matches the query against every key, turns the match scores into weights with softmax, and returns the weighted sum of values. It is a soft dictionary lookup where the "which entry matched" decision is differentiable.

Where the analogy breaks. Three places, each operationally important. (1) A dictionary returns one entry; attention returns a convex combination of all of them, so the output is always a mixture and can never be "no match". (2) The query, key and value are different learned projections of the same token vector, so "what I am looking for", "what I advertise" and "what I return" are independent — that is where the capacity comes from, and why one head cannot do everything (L07). (3) A dictionary is one lookup; attention runs n lookups in parallel, which is exactly why it is a matrix multiplication and a GPU's dream — and why the n×n score matrix is materialised, which is the cost.

What attention can do

Copy a previous token (induction heads), aggregate a global statistic, resolve a pronoun to its antecedent, retrieve a key→value pair seen in context — all with the same operation, learned.

What it cannot do

Know the order of tokens: the operation is permutation-equivariant, so positions must be injected separately (L08). It also cannot do exact arithmetic on arbitrary positions without a positional mechanism that makes them addressable.

The two axes of failure

Too flat: weights nearly uniform, the model averages everything and learns nothing specific. Too sharp: one-hot weights, gradients vanish through softmax. The sqrt(d_k) scaling is precisely the control for this.

Cost shape

n×n per head. Doubling context quadruples attention compute and memory. That single sentence explains most of the architecture choices in Track B.

3 · The mechanism #

Q = XWQ,   K = XWK,   V = XWV   (X ∈ Rn×d, W ∈ Rd×dk)

S = QKT / √dk  ∈ Rn×n
Sij ← −∞  if  j > i   (causal)  or  token j is padding
A = softmax(S, axis=1),   Aij = eSij/∑keSik
out = AV Each ROW of S/A is one query. Row i answers "how much does token i attend to each key j". Because −∞ exponentiates to 0, masking is exact: a masked key receives exactly zero weight. Rows must sum to 1 — if a whole row is masked you get 0/0 = NaN, which is why every real implementation guards or excludes those rows.

WHY divide by √dk — the variance argument

Assume each component of q and k is approximately independent with mean 0 and variance 1 (true at initialisation, and approximately maintained by normalisation). Then

E[q·k] = ∑i=1..dk E[qi]E[ki] = 0,    Var(q·k) = ∑i=1..dk Var(qiki) = ∑ Var(qi)Var(ki) = dk
⇒ std(q·k) = √dk   ⇒   Var(q·k / √dk) = 1 The raw dot product of two d_k-dimensional vectors is a sum of d_k terms, so its typical magnitude grows as √d_k. With d_k = 128, logits routinely reach ±11. Softmax with logits of that magnitude is nearly one-hot: the winner gets weight ~1 and every other key gets ~0. Its gradient is then ~0 for everything except the winner, so the model stops learning which non-winner is second best.

Two verified consequences of forgetting the scale, from Experiment 1 below: with dk = 64 the maximum softmax probability already hits 1.0000 without scaling (versus 0.8561 with it), and with dk = 8 the unscaled distribution is already visibly peaked (0.5551 vs 0.2873). The scaling is not a convention copied between papers; it is the factor that keeps the logits variance-stable as width changes — which is also why you must re-check it if you change the architecture.

The reference implementation

import numpy as np def softmax(x, axis=-1): x = x - x.max(axis=axis, keepdims=True) # stability: max-subtraction, result identical e = np.exp(x) return e / e.sum(axis=axis, keepdims=True) def attention(Q, K, V, causal=False, pad_mask=None, dropout_p=0.0, rng=None): """Q: (n_q, d_k) K: (n_k, d_k) V: (n_k, d_v) pad_mask: (n_q, n_k) bool, True = keep.""" d_k = Q.shape[-1] S = Q @ K.T / np.sqrt(d_k) # (n_q, n_k) -- scale BEFORE softmax if causal: n_q, n_k = S.shape S = S + np.triu(np.full((n_q, n_k), -np.inf), k=n_k - n_q + 1) if pad_mask is not None: S = np.where(pad_mask, S, -np.inf) # -inf, NOT -1e9 and NOT 0 A = softmax(S, axis=-1) # rows sum to 1 if dropout_p > 0: keep = (rng.random(A.shape) >= dropout_p) / (1 - dropout_p) A = A * keep return A @ V, A rng = np.random.default_rng(0) n, d = 4, 8 Q, K, V = (rng.normal(size=(n, d)) for _ in range(3)) out, A = attention(Q, K, V, causal=True) print(A.round(3)); print("row sums:", A.sum(-1)) print("row 0 attends only to token 0 -> output == V[0]?", np.allclose(out[0], V[0]))

Verified output (numpy 2.3.5):

[[1. 0. 0. 0. ] [0.827 0.173 0. 0. ] [0.34 0.413 0.247 0. ] [0.102 0.031 0.684 0.183]] row sums: [1. 1. 1. 1.] row 0 attends only to token 0 -> output == V[0]? True

Read the matrix as a lower-triangular pattern: row i has non-zero entries only in columns 0..i. Row 0 is exactly [1,0,0,0] because the only unmasked key is its own, so its output is exactly V[0] — that identity is the cleanest unit test for a causal mask and it is the test that catches the classic off-by-one (attend to j <= i, not j < i).

What it costs: the worked number for n = 8192, d = 4096

score entries = batch × heads × n × n     bytes = entries × 2 (fp16)  or  × 4 (fp32)
n = 8192, d = 4096, so 32 heads of dk = 128, batch 1:
32 × 8192 × 8192 = 2.147 × 109 score entries = 4.29 GB in fp16 (8.59 GB in fp32)
same at batch 8: 17.18 × 109 entries = 34.36 GB fp16 (68.72 GB fp32) And the model weights you are trying to fit on the same GPU are only about 0.40 GB fp32 for the four d×d projections (batch 1). The attention score matrix alone is ~11x the size of those weights — for ONE of 32 layers, ONE batch. Continue: 32 layers would need ~137 GB just for the live score matrices if they were all retained.

Also count the FLOPs, because they explain why prefill is compute-bound while decode is not: QKT is 2·n·n·dk per head; over 32 heads at dk=128 that is 2 × 8192 × 8192 × 4096 ≈ 0.55 TFLOP for a single QKT pass, and the same again for AV. At a realistic 400 TFLOP/s that is ~2.7 ms of pure matmul for one layer's attention. Twenty such layers at 1 ms each is not the problem — the materialisation is: writing and re-reading 4.29 GB of scores at ~3 TB/s costs ~1.4 ms of bandwidth per pass, and you need several passes to softmax and multiply. This is the gap FlashAttention closes by never writing S to memory (L38).

4 · Your hands #

Experiment 1 — Measure the variance claim yourself

Do not take the √dk argument on faith; measure the dot-product variance and the softmax peak. This is the diagnostic that tells you whether a new architecture can drop the scaling.

import numpy as np rng = np.random.default_rng(0) def softmax(x, axis=-1): x = x - x.max(axis=axis, keepdims=True); e = np.exp(x); return e / e.sum(axis=axis, keepdims=True) for dk in [16, 256, 4096]: a = rng.normal(size=(20000, dk)); b = rng.normal(size=(20000, dk)) dots = (a * b).sum(-1) print(f"d_k={dk:5d} var(dot)={dots.var():9.2f} var(dot/sqrt(d_k))={dots/np.sqrt(dk):.0f}") for dk in [8, 64]: q = rng.normal(size=dk); K = rng.normal(size=(6, dk)) print(f"d_k={dk}: raw max prob={softmax(q @ K.T).max():.4f} scaled max prob={softmax((q @ K.T)/np.sqrt(dk)).max():.4f}")

Verified: variance 15.97 / 254.31 / 4132.35 for dk 16 / 256 / 4096 — tracking dk closely, as the derivation predicts — and the divided versions stay near 1.0 (0.998, 0.993, 1.009). For the peaks: dk=8 gives raw 0.5551, scaled 0.2873; dk=64 gives raw 1.0000, scaled 0.8561. Falsifier: if var(dot) stayed constant as dk grew, the scaling would be unnecessary. It grows linearly, so it is necessary.

Experiment 2 — The mask test suite (run this against any attention implementation)

Four assertions that catch all the masking bugs in the table above, including the ones that only show up in mixed precision.

import numpy as np rng = np.random.default_rng(1) def attn(Q, K, V, bias=None): S = Q @ K.T / np.sqrt(Q.shape[-1]) if bias is not None: S = S + bias A = np.exp(S - S.max(-1, keepdims=True)); A = A / A.sum(-1, keepdims=True) return A @ V, A n, d = 5, 8 Q, K, V = (rng.normal(size=(n, d)) for _ in range(3)) causal = np.triu(np.full((n, n), -np.inf), k=1) out, A = attn(Q, K, V, causal) print("1 triangular:", np.allclose(A, np.tril(A))) # no weight above diagonal print("2 row0 == V[0]:", np.allclose(out[0], V[0])) print("3 rows sum to 1:", np.allclose(A.sum(-1), 1.0)) m = np.array([[0, 0, -np.inf, -np.inf, -np.inf]]) # keep only the first two keys print("4 padding invariance:", np.allclose(attn(Q, K, V, m)[0], attn(Q, K[:, :2], V[:, :2])[0]))

All four print True. Test 4 is the one people skip: masking a key must be numerically identical to deleting that key. If it is not, your mask is applied after softmax or with a finite sentinel. Test 3 is the NaN canary: a row that is fully masked makes the denominator zero, and np.allclose([nan], 1.0) is False — which is exactly how you want the bug to present.

Experiment 3 — Compute the memory bill for your own configuration

The number that decides whether a context length fits. Run it before you promise a customer 128k context.

def score_mem(n, d, batch=1, heads=32, bytes_per=2, layers=32): entries = batch * heads * n * n return entries, entries * bytes_per / 1e9, entries * bytes_per * layers / 1e9 for n in [2048, 8192, 32768, 131072]: e, per_layer, all_layers = score_mem(n) print(f"n={n:6d}: {e/1e9:9.3f} G scores, {per_layer:8.2f} GB/layer fp16, {all_layers:10.1f} GB for 32 layers") print("ratios vs n=2048:", [round((n/2048)**2, 1) for n in [8192, 32768, 131072]])

Observed: 0.27 GB/layer at n=2048, 4.29 GB at n=8192, 68.72 GB at n=32768 and 1099.51 GB per layer at n=131072 — with length ratios 16×, 256×, 4096× against n=2048. That is why 128k context is not "attention with a bigger buffer": the live score matrix is impossible, so implementations either stream it (FlashAttention) or sparsify it (L34, L38). Note the Q2 check: 4×24×40962 = 1,610,612,736 entries = 3.22 GB fp16. If someone proposes long context with no mention of this arithmetic, the proposal is incomplete.

5 · Failure modes #

  • Missing √dk. Symptom: attention entropy near zero from the first steps, loss decreases slightly then plateaus; attention maps are one-hot. Measured in Experiment 1.
  • Wrong √d. Scaling by √dmodel instead of √dk means the factor is √H too large for multi-head (L07). Symptom: soft attention that never sharpens; under-confident predictions.
  • −inf sentinel in fp16. Symptom: NaN only on the mixed-precision path, only on batches with padding. A finite sentinel such as −1e9 is outside fp16's ±65504 range and saturates to −∞, and −∞ arithmetic in some kernels yields NaN. Use a large finite value that is representable (or −inf with a kernel that handles it) and test at the target precision (L21).
  • Fully masked row. Symptom: NaN in the first forward pass, or a random-looking output at padding positions that then contaminates the loss if you forgot the loss mask too. Two independent masks are needed: attention mask and loss mask (L15, L16).
  • Softmax without max subtraction. Symptom: overflow to inf at fp16 for logits above 65504, silent underflow to uniform for very negative logits. Always subtract the row max; it is mathematically a no-op and numerically mandatory.
  • Padding mask on the wrong axis. Symptom: results depend on how many pads are in the batch; a sequence evaluated alone scores differently from the same sequence in a padded batch. Reproduce with Experiment 2, test 4.
  • Attention dropout applied after renormalisation, or scaled wrong. Symptom: attention output RMS shrinks at train time and jumps at eval; training loss is worse than eval. Dropout must be scaled by 1/(1−p) at train time and removed at eval.
  • Positional information assumed. Symptom: the model answers "the first X" and "the last X" identically; shuffle-invariance. Attention without positional encoding cannot distinguish orders (L08).

Depends on: L02 (dot product as similarity), L03 (softmax backward).   Unlocks: multi-head, KV cache, every efficiency trick in Track B.

  • L07 · Multi-head — split dmodel into H heads of dk=dmodel/H; the scaling changes with the split, which is a common bug source.
  • L08 · Positional encoding — attention is permutation-equivariant; positions must be injected somewhere.
  • L09 · KV cache — at decode you never recompute K and V for past tokens; the cache is what makes generation linear in context rather than quadratic.
  • L15 · Batching & packing — the mask tests here become the production test suite.
  • L34 · Sparse attention — attack the n×n by attending to only a subset of keys.
  • L38 · FlashAttention — never materialise S; compute the same maths in tiles that fit in SRAM.
  • L49 · Circuits — what the attention matrices actually learn to compute (previous-token, induction heads).

Audit hook: persist the attention matrices of the layer that produced a decision (or their row-entropy summary) alongside the answer. It is not proof of causation, but it makes "which evidence did the model see" queryable and it is the cheapest possible explainability artefact.

7 · Self-check #

Q1. Derive the variance of q·k and explain in one sentence why the softmax gradient matters.

Reveal answer

With independent zero-mean unit-variance components, E[q·k] = 0 and Var(q·k) = ∑i Var(qiki) = ∑i 1·1 = dk, so std = √dk. Dividing restores variance 1. It matters because softmax's gradient is p(1−p)-like: when one probability saturates near 1, gradients for all other keys vanish, so the head cannot learn to rank the runner-ups — it stops learning attention structure and only learns a hard argmax.

Q2. n = 4096, 24 heads, batch 4, fp16. How many score entries and how many GB of the score matrix does one layer need? And at n = 16384?

Reveal answer

entries = 4 × 24 × 40962 = 1.61 × 109 ⇒ 3.22 GB fp16 per layer. At n = 16384 the length factor is 4× so entries = 6.44 × 109 ⇒ 12.88 GB per layer. Both numbers are per layer and per live buffer; with 24 layers the aggregate is 77 GB and 309 GB respectively. This is why chunked/streaming attention exists.

Q3. Why must a padding mask be applied with −∞ rather than by multiplying probabilities by 0 after softmax?

Reveal answer

Multiplying after softmax destroys the normalisation: the remaining weights sum to less than 1, so the output is a shrunken combination of values — the more padding in the batch, the more shrinkage. The effect is batch-composition dependent, which makes evaluation non-comparable between batch sizes. Applying −∞ before softmax makes e−∞ = 0 and renormalises the surviving weights exactly, which is equivalent to having never included the key (Experiment 2, test 4).

Q4. Diagnostic: your loss is good, but a sequence evaluated alone gives a different answer from the same sequence inside a batch with 200 padding tokens. Which two masks do you audit, in which order?

Reveal answer

(1) The attention mask: is it keyed on the padding pattern per batch row, applied before softmax, and shape-broadcast correctly over (batch, heads, n_q, n_k)? Test with the invariance assertion from Experiment 2. (2) The loss mask: are padded positions excluded from the cross-entropy (L16)? If both are right, check that position ids reset correctly per sequence and that the model's positional encoding is not reading past the sequence end.

Q5. Attention is described as permutation-equivariant. What exactly does that mean, and what breaks if you drop positional encoding from a language model?

Reveal answer

If you permute the input tokens consistently, the output tokens are permuted the same way, because Sij depends only on the pair (xi, xj) and softmax over the set of keys is symmetric. Without positional information the model therefore cannot represent "the token before this one", "clause 4", or word order in any form — it becomes a bag-of-words model with better mixing and, under a causal mask, an artifact where a token sees only the multiset of earlier tokens (L08).
