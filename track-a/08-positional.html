L08 · Positional Encoding: Sinusoidal → RoPE, ALiBi, NoPE

Attention is permutation-equivariant: shuffle the tokens and the outputs shuffle with them, which means "dog bites man" and "man bites dog" are the same input. Every positional scheme is a patch on that blindness, and the modern patch (RoPE) encodes only relative distance because that is the only part that generalises to lengths you did not train on.

1 · Why it exists #

Look at what self-attention actually computes: Sij = qi·kj. There is no i and j in that expression except as indices into a set. Permute the tokens and every score moves with them; the result is permuted identically. So a pure transformer sees a bag of tokens. Practically:

  • "refund the fee" vs "fee the refund" — identical input.
  • "not approved" vs "approved, not" — identical.
  • An instruction at position 3 and a malicious document at position 9,000 — no notion of "before" and "after", which is precisely the boundary a prompt-injection defence needs (L93).

Recurrent models got order for free by construction; transformers had to have it engineered in. The history of that engineering is the history of what people got wrong: absolute learned positions do not extrapolate past the trained length, sinusoidal positions are absolute and drift, and relative schemes fix distance but cost either a bias term or a change to the attention computation.

Choose a positional scheme by asking one question: what happens at a length you did not train on? That deterministic failure-at-length behaviour is what your context-window promise actually depends on, and it is measurable (Experiment 3).

2 · The mental model #

Analogy. Imagine clipping an odometer to each token: absolute schemes write the exact mileage on the token, relative schemes compute "how many metres from me" when two tokens meet, and RoPE is a compass needle that rotates by an amount proportional to position — when you compare two needles, only the angle between them matters.

Where the analogy breaks. (1) Absolute schemes do not merely record position, they consume embedding capacity: a learned position table with 2048 rows and d=768 is 1.57M parameters, and rows for unseen positions simply do not exist. (2) In RoPE the rotation is applied to Q and K only, never to V — the value keeps its unrotated content, so the output is still a weighted sum with no positional contamination. (3) No scheme makes attention "understand" position; they only make the score position-dependent. What the model learns from that dependence is a training outcome, not a guarantee.

Sinusoidal (original)

Fixed, no parameters: PE[pos, 2i] = sin(pos/100002i/d). Deterministic and infinite-range in principle, but absolute: position 1000 is a different vector from position 5 and the model must generalise across offsets from data.

Learned absolute

A trainable table of max_len×d rows, added to the embedding. Simple, effective in-range, and hard-stops at max_len — the reason long-context extension of an early model needed fine-tuning.

RoPE

Rotate q and k in 2-D subspaces by an angle proportional to position. Then <Rmq, Rnk> = <q, Rn−mk>: the score depends only on relative distance. Verified below to nine decimals.

ALiBi / NoPE

ALiBi adds a fixed −slope×distance bias to scores: no parameters, cheap, natural recency prior. NoPE uses no positional signal and relies on the causal mask plus depth — in some settings measurable as competitive, which is a humbling data point.

3 · The mechanism #

Sinusoidal absolute encoding

PE(pos, 2i) = sin(pos / 100002i/d),    PE(pos, 2i+1) = cos(pos / 100002i/d)
x ← x + PE(pos)   (added before the first attention layer) Each pair (2i, 2i+1) is a sinusoid of a different wavelength: wavelengths form a geometric progression from 2π to 10000·2π, so the encoding is a coarse-to-fine counter like the digits of a number in mixed bases. The wavelength of pair i is λi = 2π/ωi with ωi = 10000−2i/d.

RoPE: a rotation whose dot product only sees the difference

θi = base−2i/d,   i = 0..d/2−1   (base = 10000 by default)
Rm rotates the pair (x2i, x2i+1) by angle mθi:
[x′2i ; x′2i+1] = [cos(mθi) · x2i − sin(mθi) · x2i+1 ; sin(mθi) · x2i + cos(mθi) · x2i+1]

<Rmq, Rnk> = qTRmTRnk = qTRn−mk = <q, Rn−mk> The identity holds because RmTRn = Rn−m — rotations compose additively. Nothing was learned to get this property; it is a consequence of the group structure. Also note: rotations preserve norms, so RoPE does not change ||q|| or ||k|| and therefore does not disturb the √dk variance argument from L06.
# RoPE — stdlib only. Rotates adjacent pairs (2i, 2i+1); the interleaved layout used by many kernels. import math def rope(x, pos, base=10000.0): d = len(x); out = list(x) for i in range(0, d, 2): theta = base ** (-2.0 * i / d) # frequency of pair i, in (0, 1] c, s = math.cos(pos * theta), math.sin(pos * theta) a, b = x[i], x[i + 1] out[i], out[i + 1] = a * c - b * s, a * s + b * c return out def dot(u, v): return sum(p * q for p, q in zip(u, v)) x = [0.4, -1.1, 0.7, 0.2, -0.5, 0.9, 0.1, -0.3] Y = [0.9, 0.3, -0.6, 0.4, 0.8, -0.2, 0.5, 0.1] q0 = rope(x, 0); k0 = rope(Y, 0) for m, n_ in [(3, 5), (100, 102), (1000, 1002)]: lhs = dot(rope(x, m), rope(Y, n_)) rhs = dot(q0, rope(Y, n_ - m)) print(f"m={m:5d} n={n_:5d} <q_m,k_n>={lhs:+.9f} <q_0,k_(n-m)>={rhs:+.9f}") print("||x||", round(math.sqrt(dot(x, x)), 9), "||R_7 x||", round(math.sqrt(dot(rope(x, 7), rope(x, 7))), 9))

Verified output (CPython 3.12):

m= 3 n= 5 <q_m,k_n>=-1.929612326 <q_0,k_(n-m)>=-1.929612326 m= 100 n= 102 <q_m,k_n>=-1.929612326 <q_0,k_(n-m)>=-1.929612326 m= 1000 n= 1002 <q_m,k_n>=-1.929612326 <q_0,k_(n-m)>=-1.929612326 ||x|| 1.749285568 ||R_7 x|| 1.749285568

That is the whole mathematical content of RoPE in four lines: a pair at distance 2 scores identically whether it sits at (3,5), (100,102) or (1000,1002). The model never sees absolute position in the score, only the gap — which is what you want when the gap distribution in training (mean few dozen tokens) must serve gaps of thousands at inference. And the norm is preserved exactly, so the score magnitudes and the L06 scaling argument are untouched.

The wavelength ladder, and where long-context breaks

Different pairs rotate at very different speeds. Compute the wavelength for a d = 64 head:

for i in [0, 2, 16, 30]: lam = 2 * math.pi / (10000.0 ** (-2.0 * i / 64)) print(f"pair i={i:2d} -> wavelength {lam:10.1f} tokens")

Verified: pair 0 has wavelength 6.3 tokens, pair 2 has 11.2, pair 16 has 628.3, pair 30 has 35,332.9. The fast pairs resolve neighbouring tokens (they change a lot per step); the slow pairs barely move and therefore saturate — at a position gap that is a significant fraction of their wavelength, the rotation wraps around and two different distances become indistinguishable. Concretely: gap 1 vs gap 49 on pair 0 (wavelength 6.3) are both ≈ full-turn rotations, so the head cannot tell them apart. This is the mechanism behind the two standard long-context interventions:

  • Interpolation / scaling: divide positions by a factor, effectively lengthening every wavelength so the trained range of angles covers a longer context. Cheap, requires fine-tuning to recover quality.
  • Base change (e.g. raising the 10000 base): lengthens the slow wavelengths more than the fast ones, preserving local resolution while extending range. Also needs fine-tuning.

Both are exactly what you would derive from the wavelength table rather than from a paper.

4 · Your hands #

Experiment 1 — The rotation invariance test (nine decimals)

Run the section-3 code. This is the unit test that should sit in every RoPE implementation: implement it wrong (rotate with the wrong frequency index, or forget to rotate K) and the invariance fails.

python -c "print('see section 3; expected: all three lines print the same value -1.929612326 on both sides')"

Observed: both sides agree to the fifteenth decimal across three very different position pairs. Falsifier check worth doing: change base ** (-2.0*i/d) to base ** (-1.0*i/d) and rerun — the single pair (3,5) still matches itself (-1.9823 both sides), so a one-pair test proves nothing; the property you must assert is that the value is the same for all gaps of the same size. Compare (3,5), (100,102), (1000,1002): a broken frequency ladder gives different numbers for the same gap. That is why the test needs three pairs, not one.

Experiment 2 — Which pairs can tell adjacent tokens apart?

Quantify the "saturation" claim rather than hand-waving it. For each pair, measure how much the rotation moves a vector for a gap of 1, 10 or 1000 positions.

def sep(i, gap, d=64): th = 10000.0 ** (-2.0 * i / d) return abs(math.cos(gap * th) - 1.0) + abs(math.sin(gap * th)) for i in [0, 2, 8, 16, 24]: print(f"pair {i:2d}: gap=1 {sep(i,1):.2e} gap=10 {sep(i,10):.3e} gap=1000 {sep(i,1000):.3e}")

Verified: pair 0 separates gap=1 by 1.3e+00 (huge) and gap=1000 by 1.265e+00 — always large because it wraps many times, so it is a modulo counter. Pair 24 separates gap=1 by only 1.0e-03 (nearly invisible) but gap=1000 by 1.301e+00. The ladder works because the set of pairs together is unambiguous, like a clock with hour, minute and second hands: any individual hand is ambiguous, the tuple is not. Consequence for design: truncating the slow pairs (some cheaper variants do) destroys long-range addressing without any local symptom.

Experiment 3 — Measure the failure-at-length, do not assume it

Whatever scheme a model uses, the honest check is behavioural: evaluate a fixed task at increasing lengths. Build a synthetic "retrieve the token at distance k" task with a toy model, or — faster and more useful operationally — test a served model's ability to answer a needle question as a function of position and length.

# minimal deterministic probe design (run against your own model / API) def probe(distance, filler_tokens=100): # document = [NEEDLE id at position distance] + filler + question "what is the NEEDLE id?" return {"distance": distance, "filler": filler_tokens, "expect": "exact id match"} for d in [10, 100, 1000, 10000, 100000]: print(probe(d))

Plot accuracy vs distance: a healthy positional scheme shows a gradual decline; a broken one shows a cliff at a specific distance (usually the training length or a wavelength boundary). Determinism matters: use a single fixed needle id and exact-match scoring so the curve is not confounded by sampling variance (L88, L94). Falsifier for "our model handles 1M context": if the curve is flat and high at 1M, you are probably measuring a pattern the model can answer without retrieving anything — include distractors.

5 · Failure modes #

  • Position offset ignored when chunking. Symptom: a document split into 8 chunks has each chunk re-numbered from 0; cross-chunk references degrade. If you chunk for cost, pass the global offset into the position ids.
  • RoPE applied to V. Symptom: attention weights look fine but the output values are position-contaminated; quality drops with length. Only Q and K get rotated.
  • Wrong frequency layout. Symptom: no crash, slightly worse quality; the invariance test from Experiment 1 fails. There are two conventions (adjacent-pair interleaved vs split-half "rotate_half") — mixing them between the training and inference code silently breaks a checkpoint.
  • Learned position table shorter than served context. Symptom: hard crash (index out of range) or silent clipping to the last row, which makes every token beyond max_len look like it is at the same position.
  • Padding positions get real position ids. Symptom: results depend on where pads were inserted; batch-of-one differs from padded batch. Pads should get position 0 and be masked out of attention and loss.
  • Interpolation applied without fine-tuning. Symptom: long-context scores degrade smoothly rather than breaking — the worst kind. Validate with a length-sweep retrieval task before promising a context window.
  • Loss-mask and position alignment drift after packing. Symptom: model learns to continue across document boundaries. Reset position ids at each sequence start, or use the packing-aware offsets (L15).

7 · Self-check #

Q1. Why does the RoPE dot product depend only on (n − m)? Write the one-line proof.

Reveal answer

<Rmq, Rnk> = qTRmTRnk. Since RmT = R−m and rotations compose additively (R−mRn = Rn−m), the expression equals qTRn−mk. No approximation, no learning — it follows from the group being abelian. Verified numerically at (3,5), (100,102) and (1000,1002) with identical results.

Q2. For d = 128, compute the wavelength of pair 0 and pair 63, and say which range of distances pair 0 can resolve.

Reveal answer

θi = 10000−2i/d. Pair 0: θ = 1, λ = 2π ≈ 6.28 tokens. Pair 63: θ = 10000−126/128 ≈ 10000−0.984 ≈ 1.15e-4, so λ = 2π/1.15e-4 ≈ 54,600 tokens. Pair 0 resolves distances well below its half-wavelength (~3.1 tokens); it aliases for larger gaps.

Q3. Diagnostic: a model trained at 4k context degrades sharply for inputs over 8k. Name the two position-related causes and how you distinguish them.

Reveal answer

(1) Learned/fixed absolute table exhausted — the crash or clipping is at exactly the trained length; check for an index clamp in the position lookup. (2) RoPE angle saturation / out-of-distribution relative gaps — degradation is gradual and begins before the trained length as gaps become uncommon. Distinguish by sweeping length 1k→12k in small steps: a step function at 4096 means the table; a smooth curve means distribution shift in distances. Both are fixed by interpolation or base change plus fine-tuning, not by prompting.

Q4. Why is a positional encoding not needed in the value path for RoPE, and what would break if you rotated V as well?

Reveal answer

Positions should only influence which values are mixed, not the content of the values. Rotating Q and K changes the scores (and hence the mixture); the value vector itself carries the information being copied. Rotating V adds a per-position phase to the output, which the next layer sees as a position-dependent distortion of content — it consumes capacity and, because the mixture weights already encode position, it creates a redundant, entangled signal. Norms are preserved either way, so nothing crashes; the damage is quality only.

Q5. The original transformer added a sinusoidal vector to the embedding. RoPE rotates Q and K. What does the change buy in one sentence, and what does it cost in one sentence?

Reveal answer

Buys: the attention score becomes a function of relative distance only, which is exactly the invariances you can hope to generalise beyond the trained length, and it needs zero extra parameters. Costs: the positional information now depends on a linear map applied after projection (so every implementation must rotate in the head dimension, and training/inference layouts must match exactly), and extreme lengths still need a frequency rescale plus fine-tuning because the slow pairs alias.
