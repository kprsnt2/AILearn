L89 · LLM-as-judge: rubrics, position bias, calibration, arbiters

A judge with a fixed leniency attenuates your signal by exactly (TPR − FPR). A judge with position bias shows you a 40-point effect that is entirely an artefact of ordering. Both are measurable in one afternoon, and neither is visible in the verdicts alone.

~40 min difficulty ●●●●● build: judge calibration report + dual arbiter
position bias verbosity bias self-preference TPR / FPR calibration attenuation factor dual arbiter disagreement routing Cohen's kappa

1 · Why it exists #

The failure: the judge is the measuring instrument and nobody calibrated it. You replace human annotation with an LLM judge because human labels do not scale. The judge produces a verdict for every item, you compute a pass rate, and you ship. But the judge has a leniency (it passes things it should fail), and if that leniency is the same for both systems in an A/B, it silently shrinks your measured effect — you see a 3.3-point difference where the true difference is 5 points, and you might not ship.

Worse is a bias that is not the same for both systems. If system A produces longer answers and the judge prefers length, the judge's verdict is partly a measurement of verbosity. If system A is the same model as the judge, the judge prefers its own style. If A and B are presented in a fixed order, the judge prefers whichever position it always sees first. These are not noise — noise shrinks with more items. These are systematic, they do not shrink, and they can reverse a conclusion.

An LLM judge is a classifier with unknown error rates, and it needs the same treatment as any classifier in a decision path: measure TPR and FPR on a human-labelled sample, report Cohen's kappa, control order and length, and route disagreements to a second independent arbiter rather than to a coin. The verdicts are not the evidence; the calibration report is.

2 · The mental model #

A judge maps (question, answer, [reference]) to a verdict. Every systematic discrepancy between that mapping and the human mapping is a bias, and each has a different mitigation. The important taxonomy is additive vs differential:

BiasMechanismEffect on an A/BMitigation
Leniency / severity (additive)fixed FPR (or FNR)attenuates gap by (TPR−FPR); direction preservedcalibrate, or report the corrected rate
Position biasprefers position 1delta up to 2×bonus; can flipevaluate both orders, count disagreements
Verbosity biasprefers longer answersfavours whichever system is more verboselength-controlled pairs; report length correlation
Self-preferenceprefers its own model's stylesystematically favours the arm from the judge's familyjudge from a different family; or judge both arms with two different judges
Rubric driftrubric interpreted differently across runs/promptsscores not comparable across timeversion and hash the rubric; re-score a fixed anchor set

Analogy: a thermometer that always reads 2° high

An additive bias is a miscalibrated thermometer: everything reads 2° high, so differences are still correct. You can even subtract the offset. A differential bias is a thermometer that reads high when the room is humid — now comparing two rooms at different humidities gives a wrong difference and no offset fixes it.

Where it breaks

A thermometer is linear and its error is independent of the measurement. A judge's error is conditional on the answer text — and the answer text is what you changed between arms. So judge error and treatment effect are entangled by construction, not by accident. Worse, a judge that is right for the wrong reason (picking a correct answer because it was longer) will keep being right on your current data and fail on the next distribution. Calibration on one sample does not guarantee calibration on another.

The consequence: measure every bias separately before using a judge in a decision path, and when a bias cannot be removed, prefer a design where it cancels (both orders, both length classes) over one where you try to correct for it arithmetically.

3 · The mechanism #

Start with the attenuated signal. If the judge passes a truly-correct answer with probability TPR and a truly-wrong answer with probability FPR, the observed pass rate for a system with true accuracy p is:

pobs = p·TPR + (1−p)·FPR   →   Δpobs = Δp · (TPR − FPR) The attenuation factor is exactly (TPR − FPR). With TPR=0.88, FPR=0.22 the factor is 0.66, so a true 5-point gap appears as 3.3 points. Direction survives; magnitude does not. A judge with TPR=FPR is useless — factor zero, all signal gone. Never report an A/B gap from a judge without this factor.

Then position bias. If the judge adds an additive bonus β to the first-listed answer, then evaluating the same pair in both orders gives:

δ = P(A wins | A first) − P(A wins | A second) = 2β Measured on a fair pair (equal true quality), δ is a pure bias estimate and should be 0. Measured on unequal pairs it shifts the whole curve by 2β. Detecting it is one loop over your golden pairs: score each pair twice with the arguments swapped.

The calibration + dual arbiter harness. Three things happen: swap-and-detect, calibrated metrics, and disagreement routing.

import random # ---------- 1. position bias: score each pair in both orders ---------- def position_bias(pairs, judge): # pairs: [(item_id, answer_a, answer_b, human_winner)]; human_winner ∈ {"A","B","tie"} a_first = a_second = 0 for _, a, b, _ in pairs: if judge(a, b) == "first": a_first += 1 # A shown first if judge(b, a) == "second": a_second += 1 # A shown second n = len(pairs) return {"a_first_rate": a_first/n, "a_second_rate": a_second/n, "delta": (a_first - a_second)/n} # delta = 2*beta # ---------- 2. calibration against human labels ---------- def calibrate(judge_labels, human_labels): n = len(judge_labels) tp = sum(1 for j, h in zip(judge_labels, human_labels) if j == 1 and h == 1) tn = sum(1 for j, h in zip(judge_labels, human_labels) if j == 0 and h == 0) fp = sum(1 for j, h in zip(judge_labels, human_labels) if j == 1 and h == 0) fn_ = sum(1 for j, h in zip(judge_labels, human_labels) if j == 0 and h == 1) acc = (tp+tn)/n kappa_p = ((tp+fp)*(tp+fn_) + (tn+fn_)*(tn+fp)) / (n*n) return {"tpr": tp/(tp+fn_) if (tp+fn_) else None, "fpr": fp/(fp+tn) if (fp+tn) else None, "attenuation": (tp/(tp+fn_)) - (fp/(fp+tn)), "kappa": (acc - kappa_p)/(1 - kappa_p) if kappa_p < 1 else 0.0} # ---------- 3. dual arbiter with disagreement routing ---------- def arbitrate(item, judge_1, judge_2, escalate): # Each judge gets BOTH orders; a judge "votes" only if its two orders agree. def solid(judge, a, b): f, r = judge(a, b), judge(b, a) if f == "first" and r == "second": return "A" # A won both orders if f == "second" and r == "first": return "B" return None # order-dependent -> no vote v1, v2 = solid(judge_1, *item), solid(judge_2, *item) if v1 is not None and v1 == v2: return {"verdict": v1, "route": "agree", "cost": 4} return {"verdict": escalate(item), "route": "escalated", "cost": 4 + 1}

Three design decisions carry the lesson. (1) Each judge must be order-consistent to vote — a judge that flips its answer when the arguments swap has no usable opinion, and counting that as a vote is how position bias becomes a verdict. (2) Disagreement escalates rather than being averaged: averaging two conflicting verdicts produces a number that corresponds to no judgement at all. (3) Cost is explicit — each judge costs 2 calls (both orders), and escalation costs one more; that is the actual bill for a calibrated evaluation.

The rubric itself matters as much as the mitigations. A good rubric is a list of checkable, independent criteria with explicit pass conditions, not adjectives:

Bad criterionWhy it failsCheckable replacement
"is the answer clear and helpful?"unanchored, length-correlated"does the answer state the four gate steps in order?" (yes/no)
"is it accurate?"subjective; judge guesses"does every numeric claim appear verbatim in the context?" (yes/no, per claim)
"rate 1-10"compresses at 7–9; scale drift across runsdecompose into 5 binary checks and sum
"is it better than the other?"invites position biasscore each independently, then compare scores

The audit artifact for a judge is a calibration report on a pinned human-labelled sample: n, TPR, FPR, attenuation factor, kappa, position-bias delta, and the length-correlation coefficient. Any judge whose verdict gates a release must be re-calibrated whenever its prompt, model, or rubric hash changes — store all three hashes next to the numbers, or the calibration is about a different instrument than the one that ran.

4 · Your hands #

Experiment 1 — Position bias shows as exactly 2β

A synthetic judge with a tunable first-position bonus, evaluated on the same pairs in both orders. A fair judge gives delta ≈ 0.

import random def measure(trials, qa=0.55, pos1_bonus=0.0, seed=0): rng = random.Random(seed) a_first = a_second = 0 qb = 1 - qa for _ in range(trials): if rng.random() < min(1, qa + pos1_bonus): a_first += 1 # A in pos 1 if rng.random() >= min(1, qb + pos1_bonus): a_second += 1 # A in pos 2 return a_first/trials, a_second/trials print("bonus A|first A|second delta_pp") for b in (-0.10, 0.0, 0.10, 0.20): f, s = measure(20000, 0.55, b) print(f"{b:+.2f} {f:.4f} {s:.4f} {(f-s)*100:+.1f}")

Observed output: -0.10 A|first 0.4498 A|second 0.6504 delta -20.1 · 0.00 0.5508 0.5494 +0.1 · 0.10 0.6519 0.4498 +20.2 · 0.20 0.7507 0.3464 +40.4. The delta is exactly 2β — a 0.20 bonus manufactures a 40-point "difference" between two identical presentations. And note the fair judge at 0.00 gives delta 0.1pp, which is sampling noise at 20,000 trials. The consequence for your eval: a judge with β=0.10 and a genuine 5-point effect will report either 25 points or −15 points depending on which arm you listed first. Falsifier: if your delta is not near 0 but the judge "seems fine" on individual items, you have confirmed position bias — individual verdicts look reasonable because the bias is small per item and only visible in aggregate.

Experiment 2 — Calibrate a lenient judge and compute the attenuation

A judge with TPR 0.88 / FPR 0.22 against human labels, then its effect on an A/B with a known true gap.

import random random.seed(1) human = [1 if random.random() < 0.55 else 0 for _ in range(200)] judge = [] for h in human: p = 0.88 if h == 1 else 0.22 # TPR / FPR judge.append(1 if random.random() < p else 0) tp = sum(1 for j,h in zip(judge,human) if j==1 and h==1) tn = sum(1 for j,h in zip(judge,human) if j==0 and h==0) fp = sum(1 for j,h in zip(judge,human) if j==1 and h==0) fn = sum(1 for j,h in zip(judge,human) if j==0 and h==1) tpr, fpr = tp/(tp+fn), fp/(fp+tn) print(f"tp={tp} fp={fp} fn={fn} tn={tn} TPR={tpr:.3f} FPR={fpr:.3f}") print(f"attenuation = TPR-FPR = {tpr-fpr:.3f}") def obs(p): return p*tpr + (1-p)*fpr for ta, tb in ((0.60,0.65), (0.60,0.55)): print(f"true {ta:.2f} vs {tb:.2f} -> judge {obs(ta):.3f} vs {obs(tb):.3f} " f"(gap {(obs(tb)-obs(ta))*100:+.1f}pp vs true {(tb-ta)*100:+.1f}pp)")

Observed output: tp=101 fp=17 fn=17 tn=65 TPR=0.856 FPR=0.207, attenuation = TPR-FPR = 0.649; then true 0.60 vs 0.65 → judge 0.596 vs 0.629 (gap +3.2pp vs true +5.0pp) and true 0.60 vs 0.55 → judge 0.596 vs 0.564 (gap −3.2pp vs true −5.0pp). The judge shrank a 5-point effect to 3.2 points in both directions — direction preserved, magnitude multiplied by 0.649. So the correct reporting is not "judge says +3.2pp" but "+3.2pp observed, attenuation 0.649, therefore estimated true effect +4.9pp ± (interval widened by 1/0.649 = 1.54×)". Falsifier: if your calibration gives TPR − FPR below ~0.5, the judge is a weak instrument and every A/B from it needs roughly 4× the items to reach the same power (L88) — or replace the judge.

Experiment 3 — Verbosity bias flips the winner

A judge that prefers the longer answer, on a pair where the shorter answer is genuinely better. Sweep the strength of the length preference.

import random def verbosity_bias(trials, p_a_better=0.55, p_a_long=0.8, p_b_long=0.3, verbosity_win=0.7, seed=0): rng = random.Random(seed) a_wins = 0 for _ in range(trials): a_better = rng.random() < p_a_better a_long, b_long = rng.random() < p_a_long, rng.random() < p_b_long if a_long != b_long and rng.random() < verbosity_win: a_wins += a_long # longer answer wins continue a_wins += a_better return a_wins / trials for vw in (0.0, 0.3, 0.5, 0.7, 0.9): print(f"verbosity_win={vw:.1f} -> A win rate {verbosity_bias(20000, verbosity_win=vw):.4f}")

Observed output: 0.0 → 0.5508, 0.3 → 0.6151, 0.5 → 0.6584, 0.7 → 0.7045, 0.9 → 0.7454. A 55% true win rate is inflated to 74.5% at verbosity_win=0.9 purely because A writes longer answers. This is the bias that most often survives into production because it looks like a quality signal — "the judge prefers A" and A really does say more. Falsifier: compute the correlation between answer length and judge score on your own data. If it is above ~0.3 you have a verbosity bias regardless of what the judge prompt says; the mitigation is to stratify pairs by length ratio or to add an explicit "ignore length; judge content only" instruction and verify the correlation drops.

5 · Failure modes #

  • Uncalibrated judge gating a release. No human-labelled sample. Symptom: the gate passes things users complain about; nobody can say what the judge's error rate is.
  • Single-order pairwise judging. A beats B in one presentation. Symptom: reversing the argument order reverses the winner for a subset of items — measured as a non-zero δ.
  • Attenuated gap reported as truth. Judge gap quoted without (TPR−FPR). Symptom: the judge shows a 3-point win and a human spot-check shows 5; you under-ship real improvements.
  • Verbosity correlation. Length predicts score. Symptom: after a prompt change that lengthens answers, scores rise with no quality change; measured by length–score correlation.
  • Self-preference. Judge is the same family as one arm. Symptom: the arm matching the judge's family wins on style-sensitive items; swap judges across families and the result moves.
  • Rubric drift. The rubric text or judge model changed between runs. Symptom: a step change in scores at a deploy; no per-item explanation. Fix: hash and version the rubric with every score.
  • Averaging disagreements. Two judges disagree and you average. Symptom: verdicts that correspond to no judge's opinion; escalation rate is near zero while calibration kappa is moderate.
  • Judge sees the reference it is grading against. Leakage. Symptom: suspiciously high agreement with the gold answer even on items where the gold is wrong; check by grading with the reference removed.

7 · Self-check #

Q1. A judge shows A ahead by 6 points. Its calibration is TPR=0.90, FPR=0.30. What is the estimated true gap, and why is the interval wider?

Reveal answer

Attenuation = 0.90−0.30 = 0.60. True gap estimate = 6/0.60 = 10 points. The interval widens by 1/0.60 = 1.67× because you are dividing an uncertain quantity by a less-than-one factor — and the factor itself is estimated from a finite calibration sample, adding its own uncertainty. So the honest report is "+6pp observed (attenuation 0.60, ±calibration error) → ~10pp estimated", with an interval roughly 1.67× wider than the raw judge interval. Always widen; never just divide.

Q2. You swap the order on 200 pairs and find A wins 62% as first-listed, 40% as second-listed. Estimate the position bonus and state the practical consequence.

Reveal answer

δ = 0.62 − 0.40 = 0.22, so β = 0.11 — an 11-point first-position bonus. Consequence: any single-order pairwise eval overstates the first-listed arm by up to 22 points, which can flip a genuine 5-point result. Practically: (a) never report a pairwise win rate without both orders, (b) judge both orders and count disagreements as ties or escalate them, (c) if a judge must run single-order for cost reasons, randomize the order per item and report the variance — but note randomization removes the bias in expectation, not the variance increase.

Q3. Two judges agree on 78% of items. What is the minimum additional information you need before treating that as evidence of judge validity?

Reveal answer

You need the base rate and their agreement against human labels. Two judges from the same model family agree because they share biases, not because they are right — a shared blind spot produces high inter-judge agreement and zero validity. Report Cohen's kappa rather than raw agreement (78% agreement at a 90% base rate is close to chance), and calibrate each judge against a human-labelled sample independently. Agreement is reliability; calibration is validity; you need both and they are not the same number.

Q4. Diagnostic: after a prompt change that makes answers 40% longer, your judge score rises from 0.71 to 0.79 with no other change. What do you check, and what do you conclude?

Reveal answer

Check the length–score correlation on the new data. A jump that tracks a length change is the signature of verbosity bias. Conclude: either quality really improved (possible if the prompt asked for more complete answers) or the judge is rewarding length. Disambiguate with a controlled comparison: take the new longer answers and truncate them to the old length, then re-score. If the score falls back to ~0.71, the gain was length; if it stays at ~0.79, the content genuinely improved. That test takes an hour and settles the question — run it before shipping.

Q5. Why route judge disagreements to escalation instead of averaging them?

Reveal answer

Because the average of two conflicting verdicts is a number no judge produced and whose error characteristics are unknown. More concretely, disagreement is informative: it concentrates on the items where the answer is genuinely borderline or where one judge's bias dominates, which are exactly the items where a human or oracle should look. Averaging throws that signal away and produces a smooth score that hides the hardest cases — so your measured quality looks better than it is precisely on the items that matter. Escalation costs (disagreement rate) × (human cost), which is budgetable; and the escalation rate itself is a health metric for the judge pair.
